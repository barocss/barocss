# Public sprite destination size: native observation

Exact base: locally integrated #794 `886eb20e84d39819adec784a0de860a23069a8f0`. This observation covers the independent native branch for #802, before Integration. The compiled package is experimental and unpublished.

Node 22.22.0 `pnpm --dir packages/barocss-canvas2d build:library` passed with a 124.4-KiB browser entry and declarations. Independent compiled-consumer `tsc -p packages/barocss-canvas2d/consumer/tsconfig.json` passed. `sprite-size-probe.mjs` passed fractional and integer dimensions, data/snapshot copies, reconstruction and continued editing, and 15 atomic invalid refusals. Existing display-tree and document probes were also run for final verification.

The actual headless Chromium 155/WebGL2 page used one 16-byte top-to-bottom 2×2 RGBA8 atlas (red, transparent, blue, green), nearest sampling, a yellow underlay, DPR2 and a centered `(0.5,0.5)` anchor at `(60,60)`. Initial 40×40 size gave `(30,50)` yellow/Back, `(50,50)` red/Sprite, `(70,50)` yellow/Back, `(50,70)` blue/Sprite and `(70,70)` green/Sprite. Changing the same sprite to 80×40 gave `(30,50)` red/Sprite, `(70,50)` yellow/Back through alpha, `(30,70)` blue/Sprite and `(70,70)` green/Sprite. Scene and tree snapshots matched. A real pointerdown at `(30,50)` routed Sprite → Team → stage. Width 80 and height 0 returned `INVALID_SCENE`, retained the previous 80×40 tree, scene, frame and hit samples.

The browser downloaded an actual [875-byte v1 document](size-document.json), reloaded the page and chooser-Opened it into a fresh generation-2 canvas/renderer/tree. The 80×40 size, samples above and all 16 asset bytes were restored. A click on **40 × 80** edited the reconstructed sprite: `(30,50)` became yellow/Back, `(50,30)` red/Sprite, `(50,70)` blue/Sprite and `(70,70)` green/Sprite. The [reopened and edited screenshot](reopened-edited.png) was inspected. After adding an inline favicon, a final reload had zero console messages. The browser and server were closed.

This one nearest-sampled asset/browser flow establishes the bounded size edit, not general image scaling quality, layout, performance, broad devices, integration or release acceptance.
