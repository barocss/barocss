## Contract, build and probe

- The declared subset is one SVG namespace root with unitless integer logical-pixel viewport, finite `viewBox`, default `xMidYMid meet` or `none`, nested `g`/`path`, ordered translate/rotate/positive-scale transforms, explicit uppercase absolute M/L/Q/C/Z, path-local `#RRGGBB`/`none` paint, nonzero/evenodd fill rules and paint alpha. Stroked paths require bevel joins and butt caps. Root viewport clipping, stable IDs, sibling layer order and `SceneV5` validation are explicit. Relative/implicit commands, arcs, matrix/skew/pivot, inherited group paint, object opacity other than 1, CSS, external references, text, images and filters refuse. The W3C SVG 2 [viewBox transform](https://www.w3.org/TR/SVG/coords.html) and [path grammar](https://www.w3.org/TR/SVG2/paths.html) informed the restricted mapping; this importer does not implement the full grammar.
- Node 22 affected `pnpm --dir packages/barocss-canvas2d build:library` exited 0; bundle 74.9 KiB. `node examples/canvas2d-scene/svg-probe.mjs` exited 0 after checking v5 JSON, IDs, 2× viewBox scale, centered meet versus nonuniform `none`, 0.5 paint alpha and arc/filter/external-use/transform-order refusal. `git diff --check` exited 0. The first probe run failed because its mock SVG element omitted DOM `nodeType=1`; the mock was corrected and the probe passed. One first browser Save command had a shell quote typo; the corrected command downloaded the file.

## Actual browser file flow

- Before import, `BeforeImport` was the visible hit at `(120,120)` with `[235,245,255,255]`. Uploading [unsupported arc](unsupported-arc.svg) returned `UNSUPPORTED_FEATURE: <path#Arc>: unsupported syntax`; the exact old canvas, pixel and hit stayed unchanged.
- Uploading [sample SVG](sample.svg) swapped to a new canvas and produced v5 context `SvgBoard`, path IDs `Background`, `SameFill`, `HoleFill`, `Ribbon`, group IDs `Artwork`, `Fills`, `Curves`, and generated wrapper IDs `SvgViewBox1`, `SvgViewport1`. Viewport `600×300` mapped `viewBox 0 0 300 150` at 2×. Same-direction nested center `(120,120)` hit `SameFill` and `[224,57,57,255]`. Opposite-direction hole `(400,120)` hit white `Background` and `[255,255,255,255]`. Outer blue fill `(320,40)` hit `HoleFill` and `[34,136,204,255]`. Transformed Q/C stroke `(160,198)` hit `Ribbon` and `[34,45,68,255]`. [Screenshot](imported-scene.png) captures the result.
- Uploading [filter](unsupported-filter.svg) returned `UNSUPPORTED_FEATURE: <path#Filtered>: unsupported attribute filter`; uploading [external use](unsupported-external.svg) returned `UNSUPPORTED_FEATURE: <use>: unsupported element use`. Both retained the same imported canvas and red sample `(120,120)`.
- Browser Save downloaded [Scene JSON](imported-scene.json) at 2,246 bytes. Uploading that exact file through Open Scene JSON swapped to another canvas and restored v5 `SvgBoard` and all four representative pixel/hit samples above. Scene JSON contains authored Canvas2D nodes; it does not retain unrepresented SVG syntax or metadata.
- The only browser console error was the unrelated missing `favicon.ico` request.

The result establishes one browser, one bounded SVG and three unsupported fixtures. It does not claim general SVG parsing, CSS cascade, SVG output parity, exact boundary pixels or other devices.
