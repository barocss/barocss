# D309 coupled native-binding and formal-reference design review

Date: 2026-10-29. Static design review only. No repository edit, build, test, probe, benchmark, commit or agent launch. The proposed wrapper was not executed or reviewed as implemented code.

## Conclusion

No material correspondence or ownership defect was found in the stated design. Two fresh existing producers can establish two results for the same owned request without a shared-prefix refactor. This establishes coupled native-position evidence and formal-reference mass evidence. It does not establish an exact closed reference for the installed B-rep, physical-solid qualification or literal stored-B-rep mass.

The reported 160132 + 33095 = 193227 operation sum is a parent-supplied baseline, not a result obtained in this review. It leaves 6773 operations before wrapper overhead under the default cap. That arithmetic does not establish that every supported input fits.

## Required correspondence and ownership

1. Create one bounded plain-own-data snapshot of the complete Part, components and options before either producer call. Deep-freeze those owned copies. Pass the same owned Part and extraction id to both calls. Do not read caller objects again after the snapshot, accept caller receipts, or use caller flags as authority. Freezing the caller object alone is insufficient: ownership must come from the own-data copy. `ownSnapshot` rejects getters, hidden/symbol fields, non-plain prototypes, cycles, sparse arrays and nonfinite numbers (`core/own-data.ts:58-95`).
2. Run `buildCylindricalWrapNativeBoundAssembly` first. Its existing path checks exactly one four-edge component without holes, rectilinear noncollapsed edges, simple nonzero rings, strict quarter/cap margins, and height equal to the actual source radius (`cylindrical-wrap-assembly.ts:263-313, 670, 845-860, 937-945`). The source and exact factor2 construction remain child responsibilities. Do not replace those checks with a four-point bounding box.
3. Derive the formal rectangle from the fresh native result's normalized `assembly.proof.components`, rather than from a second caller rectangle. Require one component, no holes, four distinct vertices, strict min/max on each axis, and exactly one occurrence of each of the four corner combinations. Check alternating horizontal/vertical edges or rely explicitly on the already admitted four-edge ring. These guards exclude any future widening of the native result from silently becoming a bounding-box mass request.
4. Select each min/max from the admitted stored Number values. Do not normalize U to [0,1], recompute the corners through arithmetic, convert UV to angle samples, round the coordinates, or reconstruct a cardinal quarter. The native result copies the admitted ring coordinates, changing only order when needed (`assembly.ts:288-289, 718-720`). Cyclic start and reversal therefore leave the rectangle unchanged. Native strict interior admission already excludes signed zero from this quarter's endpoints.
5. Pass that rectangle and the same owned density/budgets to `certifyCylindricalWrapFormalPadMass`. The latter independently copies and revalidates the actual source, requires a strict native-U/V rectangle, reads the original quarter coefficients, and computes actual endpoint rays and exact affine source Z (`cylindrical-wrap-formal-mass.ts:118-134, 279-304, 343-350`). `sourceCore` validates the full original B-rep against the same actual prismatic source and extracts the quarter by direct copy (`cylindrical-wrap-source.ts:161-185`). The wrapper must use the same extraction id; it must not add separate source/radius/rectangle overrides.

Because the owned input is immutable and the synchronous existing producers independently validate it, a prefix-sharing or source-receipt continuation is not required for correspondence. A small explicit binding receipt may name the derived rectangle and source id, but it must not claim equality of the ideal formal boundary and the installed rounded rational boundary.

## Aggregate accounting conditions

- Subtract the **complete** `nativeBinding.counts.exactOperations`, plus any charged wrapper arithmetic already executed, from the requested aggregate maximum. Do not subtract `assembly.proof.counts`, the assembly phase or a nested prefix: these omit later native phases. Require at least one remaining operation before calling formal mass; never clamp a nonpositive remainder to one.
- Pass the remainder as formal `maxOperations`. The formal total already includes its second source admission. Add `formal.counts.totalOperations` once to the native total; never deduct either source cost for matching inputs. Imported source counts, side/component cumulative receipts and the D0 family must not be summed again from nested fields.
- Add complete `nativeBinding.counts.work`, complete `formal.counts.work`, and wrapper structural/direct work once. The current native and formal work totals both include their imported carrier rational/GCD/search costs and direct work in their own normalized total paths. Use `max(native.maximumBits, formal.maximumBits, wrapperMaximumBits)`, not a sum, for the 8192-bit guard. Check final aggregate operation/work/bit limits after all new output construction and freezing charges, before publishing a result.
- Preserve every child internal limit, including its rational/GCD/float-search checks. A wrapper using independent child contexts is not one physically shared `SectionRationalContext`; do not describe it as such or imply a new aggregate GCD-counter guarantee that the wrapper does not expose. The authoritative new aggregate contract is the stated exact-operation/work/maximum-bit contract plus unchanged child checks.
- Neither source helper nor the formal helper accepts a remaining-work parameter. A rejected request can execute a child before the final aggregate work check observes exhaustion. State that failure-checkpoint limitation. It does not justify accepting an over-budget result, returning a partial native result, restarting with a fresh allowance or automatically changing tolerances/budgets.

## Scope that must remain open

The native result already keeps source-global, retained-face closure, orientation, physical B-rep, solid, represented-volume, surface-endpoint and product claims false (`assembly.ts:930-934`). The formal result keeps literal stored-B-rep mass, wrapped solid, native binding, surface area, Part mass-provider and native-SI accuracy false (`formal-mass.ts:357-361`). Keep these child meanings intact. A new top-level coupling claim should name only same owned request / derived rectangle / two fresh proofs / accepted aggregate budget. It must not promote either child proof into the missing closed-reference or mass-transfer theorem.

No additional design blocker was identified. Implementation still needs the owned-input/rectangle mapping and final-accounting checks above, followed by parent-run equality, failure-atomicity and tighter aggregate-budget tests. This review supplies no runtime PASS or performance claim.
