# D346 검증과 인수인계

단일 비직선2차 곡선의 고정 방향 CUT 배치를 Kernel·공유API·Model·실제Studio에 연결했다. 제어점3개, 가중치1, 일정한Z의 곡선이 범위다. 기존 직선 계산 본문과15개 배치·거절 값은 유지했다. 문서 버전·의존성·공차·전체 작업 한도는 바꾸지 않았다.

커널31개, Model97개, 타입·영향 범위lint·API·생성 문서 검사와 Studio build/chat23개가 통과했다. 단순 callback 이동과 오래된 테스트 설명 수정 뒤 커널12개·Model8개를 재검사했다. 고유 검사 개수를 중복 합산하지 않았다.

64개 요청의 첫200k 거절을 보존했다. 후보·상수·정수제곱근 제안 재사용으로 개선했다. 독립 감사는 decoder 반복 비용 예약과 배열의 범위 밖 숫자 키를 추가로 발견했다. 같은 checked owner와 원래 경로 검사를 유지한 endpoint 경로,16384 선예약 및 canonical index 검사로 수정했다. 최종 공개64요청은196882/200000,63pole 반쪽 좌표 사례는28477이다. 모든64곡선을 지원한다는 뜻은 아니다.

지정 perf-bench.mjs의 전후 비교는 개발 중 고정 빌드 기준이다. Node22, 준비3회·측정7회·batch1에서 실제3CUT 전체 생성 중앙값은 곡선5.135833→4.430542ms, 직선2.591125→2.506709ms다. 형상·개수·이름·부피·질량 중심 조건은 SAME이다. 곡선 비트는 달라졌고 직선 비트는 같다. 한 쌍의7표본으로 일반 속도 향상이나 Studio 입력 지연을 단정하지 않는다. 원본 JSON과 [성능 보고서](perf/report.ko.md)를 유지했다.

실제 첫 흐름은 적용 뒤 비교용420 객체가 잘못 선택되는 오류였다. 성공한 Path 적용에만 선택 해제를 추가한 뒤 두 번째 흐름이 통과했다. Chrome하나·문맥3개를 순서대로 실행해 관찰12건, native읽기9건, 독립Decimal검증6건, 실제저장2건과 새 문맥 열기를 확인했다. 곡선 실제 생성, 미리보기·거절·취소·적용, 간격 변경, live제어점 편집, 평행 이동, Undo/Redo와 파일 편집성을 확인했다. source979개 전후가 같고 오류0, 자원도 모두 닫혔다.

화면6장을 별도로 확인했다. 원본Z0 곡선은 본체에 가려지지만 제어점·입력·곡선 진단과 결과구멍을 확인했다. 화면과 반올림 표시는 정밀 좌표·질량의 근거가 아니다. native꼭짓점·닫힘·이름·목표 객체와 witness의 독립 구분, 부피23550과 중심을 별도 수치로 확인했다.

보존한 첫 실패에는 Kernel fixture누락/공개작업량, 잘못된lint경로, Model의 예전 거절 문구, 테스트 TS2783/TS2550/TS7006와 unused import, Core감사 두 항목, 실제 선택 오류가 있다. Model두 assertion은 VALUE와 새 구체적 사유를 확인하며, 기존 정상 cancellation/subnormal검사도 통과했다.

이번 변경의 전체Kernel·전체Model·전체Studio는 실행하지 않았다. 원격CI·develop병합은 사용자 요청에 따른 별도 통합 단계다. 범용곡선·다중span·rational·임의frame·도구회전·범용B-rep교체·일반선택재매핑·release는 완료 범위가 아니다. 다음은 기존 비트림 Extend의 실제 소비자 검증이다. 이번 세션에서는 새 기능을 시작하지 않고 Claude로 인수인계한다.
