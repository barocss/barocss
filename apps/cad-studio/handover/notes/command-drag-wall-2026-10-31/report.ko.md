# D368 보고 — 핸들 드래그 값이 튀던 문제 수정 (로드맵 20 ②)

사용자가 직접 본 "필렛 화살표를 끄는 중 값이 다른 숫자로 튄다"를 재현하고 고쳤습니다. 09에서 B1로 넘어가는 경계에서 처리했습니다. 소스 커밋은 `58f9e045f`입니다.

## 문제

드래그 도중 미리보기 결과가 커널에서 늦게 도착하면 다음 문제가 생겼습니다.

- 이미 지나간 값의 거절이 현재 값을 되돌렸습니다.
- 한 번 거절되면 그 방향은 드래그가 끝날 때까지 막혔습니다.
- 마지막으로 샘플한 값에서 멈춰서 한계보다 한참 낮은 값으로 끝났습니다.

## 수정

- 거절은 그 값이 지금 값일 때만 값을 되돌립니다. 늦게 온 거절은 "여기부터 안 된다"는 경계로만 기록합니다.
- 경계 아래 값은 계속 시험하고, 중간값 탐색(bisect)으로 실제 한계까지 수렴합니다.
- 놓은 뒤에도 탐색이 이어지고, Apply는 탐색이 끝날 때까지 기다립니다.
- 늦게 온 성공이 값을 뒤로 되돌리지 않습니다. 그래서 값은 한 방향으로만 움직이고 멈춥니다.

## 감사와 실패 기록

- **독립 감사**: 첫 수정이 새 흔들림을 만들었습니다(포인터를 경계 밖에 두면 4↔5.5로 오감). 이를 고쳤고, 값의 순서를 확인하는 테스트를 추가했습니다. 시간 단축을 위해 재감사는 생략했습니다.
- **실제 실행**:
  - run01: 빠르게 되돌아올 때 9가 "evaluating…"으로 한 번 보였다가 7.5로 돌아왔습니다. 값은 화면에 보여야 시험할 수 있으므로, 포인터 이하에서 한 번 보이는 것은 허용하고 흔들림은 금지하기로 정했습니다.
  - run02: 표시 값이 한 프레임 늦는 것을 드라이버가 실패로 잡았습니다. 이 오차는 run01에도 있었습니다. 흔들림 기준은 그대로 두었습니다.
