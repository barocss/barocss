## Candidate boundary

Pinned Python `-B candidate.py` imports the pinned ORIGINAL full-pair world
reference and calls its ORIGINAL main. It installs a wrapper ONLY around world.
kernel/step-ledger, JSON parsing, exceptions, routing, compact serialization and
physical reply keys remain original. No timing/cache metadata enters replies.
The wrapper calls original_world exactly once inside a temporary Scope, then
restores the original SAT function objects and clears all preparation tables
in finally, also after exceptions. There is one synchronous request per worker;
nesting is an integrity error. No other worker or global Decimal setting changes.

Only three SAT call boundaries are wrapped: decode_body, sat_pair and
quaternion_basis. Their original mathematical functions remain the function
objects loaded from immutable source. Original sat_pair executes EVERY time;
its quaternion normalization divisions, all15 axes/support calculations,
zero/near-parallel classification, winners/ties and output construction remain
unchanged. sat_pair wrapper merely identifies its two existing basis calls.
No support radius, axis result, pair result, midpoint, optimum or producer result
is memoized. Cold LP/QP, exact arithmetic, counters and native comparison are
unchanged. There is no integer SAT, Gram reassociation, witness authority change,
axis/point removal or capacity/numerical fallback.

Reuse is local to ONE world request. A body key contains id, kind, EXACT ten
Float64 geometry words (center3/extents3/quaternion4), and full current Decimal
context: precision, rounding, Emin/Emax, capitals/clamp, all nine traps and all
nine incoming flags. Signed zeros remain distinct. Decode errors are never
stored. Invalid or non-native key operands still invoke the original decoder
once and retain its original error/admission behavior; this is a normal miss,
not an alternative solver or relaxed admission. The key never includes velocity
or mass because decode_body does not read them; the original scalar query still
validates those fields separately on every call.

Prepared decoded dictionaries are private snapshots. Every hit returns a NEW
dictionary; its tuple/Decimal leaves are immutable. Raw caller arrays are not
retained. Input mutation changes the word key. A retained token holds strong
references to the actual immutable quaternion tuple and norm Decimal, preventing
ID reuse. The basis key uses that token, the original raw/normalized mode and
the full context. For normalized mode, original sat_pair still computes the
actual divided quaternion under that same context before the basis lookup.
These inputs uniquely determine the original basis. Unregistered decoded
objects are computed normally without reuse. Returning the immutable basis
tuple by identity is allowed; mutable result dictionaries cannot alias tables.

Post-flags are recorded after each SUCCESSFUL original preparation. Hits require
identical incoming flags/settings/traps and replay the exact recorded post-flags.
Thus sticky signals, enabled traps, signed Decimal zero and Decimal exponents
are retained. There is no context serialization, persistent cache, Context
normalization or reuse across80/120/ambient admission precision. PRE/HYP poses
have separate full geometry keys; unchanged orientation is NOT assumed from
producer claims. Existing raw-body and held-bit checks remain original.
