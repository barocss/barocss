# Editable display tree document Open

Issue: https://github.com/barocss/barocss/issues/753. Native parent: locally integrated #747 `ff87148547112d07810ac6e53766a387ed912aa3`. This is Execute evidence before Integration.

Node 22.22.0 `pnpm --filter @barocss/canvas2d build:library` passed with public compiled JavaScript (98.3 KiB) and declarations. `tsc -p packages/barocss-canvas2d/consumer/tsconfig.json`, `node examples/canvas2d-scene/display-tree-reopen-probe.mjs` and the earlier `display-tree-probe.mjs` passed. The reconstruction probe read the prior actual 940-byte document, matched canonical Scene v6 and all 16 asset bytes, found Blue then Red under Team, tested attached-only `get`, edited reconstructed handles without changing input, preserved an optional source crop, and refused an invalid ID, Scene v5, a v6 rectangle and malformed Scene. No implementation test failed in this slice.

Opened `http://127.0.0.1:57018/packages/barocss-canvas2d/consumer/display-tree.html` in Headless Chrome 155. The import map used only compiled `@barocss/canvas2d` and `/document` entries. WebGL2 backing size was 640×400 for a 320×200 logical canvas at DPR 2. The page downloaded the actual 940-byte [v1 document](saved.json) from Team with Red and Blue image handles and one copied 2×2 RGBA8 asset (16 bytes). Moving Team from x=40 to x=60 changed (50,60) to transparent/null and (90,80) to blue/Blue.

The file chooser Open of that downloaded document made a fresh canvas and fresh tree (`newCanvas:true`, `newTree:true`, generation 2). The accepted Scene and new tree snapshot had equal canonical JSON, the saved original Scene was restored, `get('Team')` returned a container and `get('Red'|'Blue')` returned sprites, and all 16 asset bytes matched. Team's children were Red then Blue. (50,60) was red/Red and (90,80) was green/Blue. The old renderer reported `DISPOSED`.

After Open, the authoring controls remained enabled. Moving the reconstructed Team to x=60 and centering Red's anchor produced matching accepted Scene and tree snapshot. Actual WebGL2 readback and hit test returned (50,40) `[255,0,0,255]`/Red, (50,60) `[0,0,255,255]`/Red and (90,80) blue/Blue.

The chooser then tried a valid v1 [document with a Scene v6 rectangle](unsupported-rect.json). It returned `UNSUPPORTED_FEATURE` and retained the exact same canvas DOM object, tree object, accepted Scene, samples and asset bytes. A [document with a corrupt asset digest](corrupt-digest.json) returned `INVALID_ASSET` and retained those same objects and values. The [screenshot after refusal](retained-after-refusal.png) shows the edited image scene and refusal status. The candidate renderer was disposed for the unsupported tree, and parsing the corrupt file did not create a candidate. The only browser console error was the static server's missing `/favicon.ico`; there was no module load error.

This is one local browser/GPU and file run. It does not establish general PixiJS feature parity, frame rate or broad browser support. The compiled consumer accepts only the fixed Team/Red/Blue shape after Open; the public reconstruction function accepts any valid Scene v6 group/image tree within existing limits.
