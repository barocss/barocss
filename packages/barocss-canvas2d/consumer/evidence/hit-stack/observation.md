# C2D-49 native browser observation

The compiled consumer ran in headed Chromium 155 with a real WebGL2 canvas at logical 80 × 80 and DPR 2. The initial sample at logical (20,20) was blue RGBA `[0,0,255,255]`. `hitTest` returned `Sprite`; `hitTestAll` returned `Sprite`, then `Rect`. A real mouse pointerdown used the second hit. The existing display tree delivered `Rect → stage` while the pixel stayed blue.

Setting `Sprite` hit mode to `none` kept the same blue pixel and changed both the top hit and hit stack to `Rect`. Another real pointerdown delivered `Rect → stage`. The browser downloaded the attached 861-byte v1 Scene v11 document. A chooser Open staged a fresh canvas, renderer and display tree. The reopened asset bytes were `[0,0,255,255]`; the blue pixel and `Rect` stack remained. Editing the restored sprite back to `auto` restored `Sprite, Rect` and a second-hit pointer route to `Rect → stage`. The old tree's pointer log remained unchanged after Open. The screenshot shows this reopened and edited state.

Additional actual WebGL2 queries used the existing compiled consumers. A filled path under an image returned `Image, Filled`, and its hole returned no hit. A clipped frame returned `Overhang, Window, Paper` inside the clip and only `Paper` outside it. Two separate glyph quads from one glyph run each returned `Title, Paper`; empty glyph pixels returned only `Paper`. A 2 × 1 RGBA asset returned `Front, Back` on its opaque cell and only `Back` on its transparent cell. Setting the front sprite's alpha to zero, visibility to false, or hit mode to `none` each left only `Back` in the stack. A pan/zoom view still returned `Front, Back` at the mapped point. On the path consumer after adding a stroke, the same `Filled` path ID appeared once on its border.

The path, frame and glyph pages each logged one missing `favicon.ico` request; that request did not affect WebGL2 or the queries. The hit-stack consumer itself logged no browser warning or error.
