# #457 frozen baseline, before case translation

This is a bounded authored comparison, not a model trial or a sampled user population. `baseline.json` was frozen before the edit cases were written. `freeze.mjs --verify` checks the exact #446 semantic/catalog source files, theme CSS, released 0.11.2 BaroCSS browser bundle, typed variable policy, state template, compiled CSS inventories and local browser/runtime provenance. The official json-render 0.21.0 install and Playwright/Chromium are the approved existing read-only assets; no new download is needed.

All arms use the #446 settings, dashboard and kiosk nodes, state bindings, focus targets, actions, host CSS and theme. The preset arm carries #446's bounded density, column and placement props. The variable arm carries the same bounded props; density selects 24px regular or 12px compact padding/gap defaults, and a validated finite numeric override may set padding/gap (8–32px) or radius (0–24px), including fractions. The registry formats those numbers as `px`; no author string becomes CSS. Placement and columns are coupled in the authored #446 stages (`side`/2, `stacked`/1); the original renderer did not use placement independently. This limitation applies equally to preset and variable arms.

The only baseline catalog extension is a Boolean button `hoverUnderline` selector in preset and variable arms, backed by the frozen `hover:underline` class. It shows that selecting an already compiled state rule does not require runtime rule generation. It is distinct from changing a numeric value through a CSS variable. The utility and build arms may carry the same authored class tokens in `className`; only utility uses the existing BaroCSS preload. The build arm's CSS inventory is frozen at initial tokens. No arm may add a template during the primary run. A rule absent from these inventories is reported separately from a failure of an existing rule.

The initial utility and build CSS hashes must be identical. Their later behavior may differ because the utility arm can add discovered rules at runtime. The baseline explicitly excludes model calls, external data, arbitrary CSS/HTML/JS, URL-bearing values and adaptive catalog expansion. Hypothetical new presets/templates belong in the decision report, not the primary results.
