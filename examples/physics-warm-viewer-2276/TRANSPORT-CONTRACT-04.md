# Data transport algorithm 04

The desktop02 browser passed ten screen checks and retained its complete proof. The unchanged decoder then refused the full-root fingerprint before any physical observer ran: its JSONEncoder emitted more than 1,000,000 fragments. Preserve that actual protocol refusal. It is not a physical failure and is not retroactively an old-decoder PASS.

This new data-only algorithm verifies the same full canonical UTF-8 bytes and SHA-256, with sorted object keys, no whitespace, and ensure_ascii=False. It imports no physics, renderer, candidate, or observer. No browser or World rerun is needed. The author does not execute it.

Keep 16 MiB per expanded canonical value, at most 8192 shared dictionary nodes, and maximum reference/expanded value depth 64. Keep a cumulative limit of 1,000,000 actual emitted byte fragments across every node verification and the root verification in one decode. Each emitted fragment is at most 4096 bytes. This is a new measured cost model: one verified subtree byte span is one actual hash update, rather than the old encoder's many repeated lexical fragments. Do not call it an old-fragment-protocol PASS. No scalar or whole-root json.dumps bypass is used. String escaping streams into bounded chunks; no unbounded expanded-root string is allocated.

Resolve original $node references with missing/cycle/depth checks. Verify each resolved original dictionary node against its own full canonical SHA before admitting any span. Only an original referenced list/dict whose full canonical representation is at most 4096 bytes can enter an operation-local span cache; total admitted byte payload is at most 4 MiB. A full cache stops new admission; it does not waive verification or any bound. Larger nodes always stream, using already verified descendant spans where available. Root verification hashes every canonical byte, including every repeated occurrence; cached digests never stand in for content. Reference/pool completeness and unused-node checks remain mandatory. Cache spans also retain subtree height so a cache hit cannot bypass expanded-depth checks.

Cache storage and decoded reference storage are distinct. Decoded output retains ordinary shared list/dict objects, as before. The verified span cache is discarded before returning. A consumer mutation cannot affect a later decode or make a later fingerprint reuse stale bytes. Callers must bound stored JSON bytes to 16 MiB before JSON parsing; this module accepts an already parsed plain JSON value. A declared expanded byte value is not accepted as proof: it must equal the independently streamed root byte count.

Public interfaces are `decode_packet(packet)` and `decode_packet_with_receipt(packet)`. The latter returns `(decoded, receipt)`. The receipt includes `rootCanonicalSha256`, `rootCanonicalBytes`, `verifiedNodeHashes` (every original key mapped to its computed SHA), `verifiedSharedNodes`, `emittedFragments`, `emittedCanonicalBytes` (cumulative work, not root size), `canonicalJobs`, `cacheEntries`, `cacheBytes`, `cacheHits`, `cacheHitBytes`, `maxEmittedSpanBytes`, and `maximumExpandedDepth`. All old exported MAX constants retain their values. `fingerprint(value)` remains a separate ordinary bounded canonical stream with no inherited reference cache; it is for independent small-value checks and is not a route around the decode proof.

Qualification must compare old/new canonical output on small independently authored JSON/DAG cases and qualified Native packets. It must check the browser root against its original declared full SHA/byte count and verify all pool hashes. Include wrong root SHA/bytes, changed node payload, missing/cyclic/unused references, oversized declaration, too many nodes, depth overflow, and actual emitted-fragment overflow. Include escaped/control/non-ASCII strings, scalar types, key order, repeated aliases, and mutation followed by fresh decode. Preserve all negative receipts. If the new resource meter refuses the actual proof, save that refusal; do not raise a cap or drop data. Independent physical observers remain unchanged and NOT_RUN until data qualification actually passes.
