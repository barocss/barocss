# BaroCSS 0.0.4 후보 독립 검증

작성일: 2026-09-23
담당: Baro Guard
상태: 통합 커밋 `3240100`의 독립 검사와 선택한 Chromium 렌더링 검사 통과. 후보 결정은 PM·Mento 담당.

## 검증 대상

기준 커밋은 `4462645`다. PM은 코드 변경을 `aa64035`에 통합한 뒤 문서 보정 `ab216c1`, 버전 변경 `2431d2d`를 적용했다. 검증한 최종 커밋은 `3240100`이다.

| Work | 검증에 사용한 변경 |
| --- | --- |
| Core | `d590939` 설정 격리, `a749cd4` hover 조건 |
| Pulse | `e96aae6`, `2fa60ca`, `a380934`; Pulse의 `HEAD`에 Core `d590939` 병합 포함 |
| Mirror | `b60ff82`의 effects와 Tailwind 4.1.13 비교, `57ddefb`와 `5682ad1`의 문서 보정 |
| Ship | 패키지 경로, CI, `check-packages.mjs`, LICENSE 변경과 세 패키지의 `0.0.4` 버전 정합성 |

Core와 Pulse의 커밋 diff 및 회귀 테스트를 직접 읽었다. Mirror와 Ship 변경을 먼저 임시 조합에서 검사했다. 이어 PM 통합 코드 `aa64035`와 버전 변경을 포함한 `3240100`을 각각 별도 디렉터리에서 검사했다. 작업자의 원본 트리에는 쓰지 않았다.

## 후보 통과 기준

1. 각 Work의 변경 파일과 공개 API를 PM이 검토한다. 중복 적용과 누락이 없어야 한다.
2. Node 22와 pnpm 9에서 `pnpm install --frozen-lockfile`, `pnpm check`가 통과해야 한다. `pnpm test` 로그에는 kit, browser, server가 모두 있어야 한다.
3. 설정이 다른 두 Context에서 같은 클래스를 교차 생성해도 CSS, 실패 캐시, 등록된 utility와 modifier, CSS 변수 접두사가 섞이지 않아야 한다.
4. 브라우저에서 DOM 추가·변경, `updateConfig`, `clearCaches`, `destroy` 후의 스타일과 캐시가 회귀 테스트를 통과해야 한다. 서버의 빈 문자열·공백·빈 배열 입력도 검사한다.
5. `pnpm build:library` 후 `node .github/scripts/check-packages.mjs`가 세 tarball의 exports, ESM, 서버 CJS, 타입, browser CDN 경로를 검사해야 한다.
6. Tailwind 기준 버전과 fixture를 고정하고 구조 차이를 기록한다. 문서에는 측정하지 않은 호환율 또는 완전 호환을 표시하지 않는다. 동작 차이가 남으면 PM이 범위와 우선순위를 정한다.
7. 세 패키지의 버전, 내부 의존성, lockfile을 대조한다. GitHub CI에서 동일 검사를 확인한 뒤 후보 상태를 결정한다.

## 직접 실행한 검사

Node는 `v22.22.0`, pnpm은 `9.15.4`였다. PM 통합 커밋 `3240100`을 빈 디렉터리로 복사했다. 다음 명령을 순서대로 실행했다.

```sh
pnpm install --frozen-lockfile
pnpm check
node .github/scripts/check-packages.mjs
```

고정 lockfile 설치에 성공했다. 설치된 Vitest는 `3.2.4`다. 전체 `pnpm check`에서 kit 41파일·1,418개, browser 10개, server 2개 테스트가 통과했다. 타입 검사, lint, 세 패키지의 빌드도 통과했다. Lint에는 browser의 기존 `no-explicit-any` 경고 2개가 남았다. pack 검사는 세 패키지의 `0.0.4` 버전과 내부 의존성, exports 실파일, ESM import, 서버 CJS require, 타입의 NodeNext 컴파일, CDN JS import를 통과했다. Tailwind 비교 테스트 18개도 전체 검사에 포함됐다.

GitHub [CI 실행](https://github.com/barocss/barocss/actions/runs/35807519957)도 `3240100`에서 성공했다. 기본 sandbox는 레지스트리 연결이 막혀 있어 로컬 clean install에는 네트워크 접근을 허용했다.

## 선택한 클래스의 실제 브라우저 검사

`pnpm build:library` 뒤 다음 명령으로 Tailwind CSS 4.1.13과 BaroCSS의 CSS를 각각 넣은 독립 HTML 페이지를 만들었다. `@theme inline`의 breakpoint는 양쪽 모두 `48rem`이다. 로컬 HTTP 서버에서 Playwright CLI의 Chromium `153.0.8010.53`으로 열었다.

```sh
node docs/verification/render-compat-fixtures.mjs /tmp/barocss-render
python3 -m http.server 8765 --bind 127.0.0.1 --directory /tmp/barocss-render
```

| 입력 | 확인 방법 | Tailwind / BaroCSS 결과 |
| --- | --- | --- |
| `hover:block` | 데스크톱 hover 전후의 `display`; 터치 기기 모드에서 탭 후 `display` | 데스크톱 `inline-block → block`으로 같음. 터치 기기에서 `(hover: hover)`는 거짓이고 탭 후에도 둘 다 `inline-block`. |
| `md:block` | viewport 767, 768, 769px에서 `display` | 양쪽 모두 `none`, `block`, `block` 순서. |
| `mask-linear-from-50%` | `mask-image`, `mask-composite` 계산값과 100×100 요소의 PNG | 계산값이 같고 PNG 바이트가 동일함. 빨간 요소에 50%부터 적용되는 mask 효과를 이미지로 확인함. |
| `inset-ring-2` | `box-shadow`, `color` 계산값과 100×100 요소의 PNG | 계산값이 같고 PNG 바이트가 동일함. 파란색 2px 안쪽 ring을 이미지로 확인함. |

브라우저 페이지는 버전 변경 전 코드에서 만들었다. `3240100`의 네 입력에 대한 CSS가 그 페이지의 CSS와 바이트 단위로 같은 것도 확인했다. 이 결과는 해당 네 입력의 기본 상태와 Chromium 환경에 한정된다. Firefox의 현재 Playwright 실행 파일은 설치되지 않아 검사하지 못했다. WebKit, 다른 테마 조합, 전체 Tailwind 기능 범위도 미검증이다.

GitHub 저장소 API는 easylogic 계정의 admin, push, triage 권한과 Issues·Wiki·Discussions 활성 상태를 반환했다. 기본 sandbox의 `gh auth status` 실패는 네트워크 차단 때문이었다. Issue와 Wiki의 중복 관리와 게시는 PM·Steward가 맡는다.

## 후속 검증 항목

`md:block`은 Mirror의 최종 fixture에서 양쪽 모두 `48rem`을 쓴다. 쿼리 문법과 중첩 구조는 다르지만 이 입력에서 적용 경계 차이는 확인되지 않았다. 따라서 결함 Issue로 분류하지 않는다. 구조 차이는 호환 문서에 남긴다.

### P2 — `inset-ring-2`의 다른 테마와 브라우저 동작을 검증

- 담당 제안: Mirror.
- 재현: 위 비교 명령에서 `inset-ring-2` fixture를 실행한다.
- 기대: Tailwind CSS 4.1.13과 같은 기본 색과 ring 표현을 제공한다.
- 실제: 기본 색의 Chromium 계산값과 픽셀은 같다. BaroCSS의 사용자 정의 속성과 Tailwind의 `@property` 규칙 구조는 다르며, 다른 색·그림자 조합과 브라우저의 동작은 미확인이다.
- 수용 기준: 기본 테마와 상속 색을 바꾼 브라우저 예제로 computed style을 비교하고, 차이를 수정하거나 지원 범위를 기록한다.

### P2 — `mask-linear-from-50%`의 다른 조합과 브라우저 동작을 검증

- 담당 제안: Mirror.
- 재현: 위 비교 명령에서 `mask-linear-from-50%` fixture를 실행한다.
- 기대: Tailwind CSS 4.1.13이 생성하는 mask 효과를 제공한다.
- 실제: 기준 커밋에서는 BaroCSS CSS가 비어 있었다. Mirror 변경 뒤 기본 Chromium 계산값과 픽셀은 같다. Tailwind의 전역 `@property` 기본값과 CSS 구조는 다르며 다른 mask 조합과 브라우저는 미확인이다.
- 수용 기준: mask 합성 결과를 브라우저에서 비교하고, 필요한 기본값을 제공한다. 남은 차이는 문서에 기록한다.

## Wiki 갱신안: 0.0.4 검증 절차

1. 기준 커밋, 통합 커밋, Node·pnpm 버전, lockfile 상태를 기록한다.
2. `pnpm install --frozen-lockfile`, `pnpm check`, `node .github/scripts/check-packages.mjs`를 순서대로 실행한다. Test Files와 Tests 수를 세 패키지별로 기록한다.
3. `packages/barocss/tests/compat/fixtures.ts`의 Tailwind 버전과 입력을 고정한다. `match`, `different`, `unsupported`를 구분한다. 표본 결과를 전체 호환율로 쓰지 않는다.
4. Context 격리, DOM 변경, 설정 갱신, 종료, 서버 빈 입력의 회귀 테스트를 확인한다.
5. 구조 차이가 있는 우선 입력은 `render-compat-fixtures.mjs`로 HTML을 만들고 실제 브라우저의 계산값과 픽셀을 비교한다. 확인한 브라우저·상태·테마 범위를 기록한다.
6. PM이 diff, CI 결과, 남은 동작 차이, 버전 정합성을 검토한 뒤 후보 상태를 기록한다. 후보 판정은 npm 게시 승인이 아니다.
