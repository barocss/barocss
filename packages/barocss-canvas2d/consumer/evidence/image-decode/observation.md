# Public raster Blob decoder compiled-consumer observation

Issue: https://github.com/barocss/barocss/issues/777. Native parent: locally integrated #756 `77332bddd4841ad78754fb88cf7c036a29786af7`. This is Execute evidence before Integration.

Node 22.22.0 package build passed (108.4 KiB compiled browser entry). The independent `checkJs` consumer type check passed with `image-decode.mjs`. `image-decode-probe.mjs` passed eight refusal cases, three temporary bitmap closures after success/limit refusal, and a copied 16-byte RGBA8 result. The browser run below used the real decoder; the Node probe used controlled browser API doubles only for resource/error cases. The existing `document-probe.mjs` passed. The existing `image-probe.mjs` first failed because its expected asset list omitted the already present `GlyphHI` fixture in the exact #756 parent. Its expected list was corrected to include the 280-byte glyph atlas; the probe then passed.

Headless Chrome 155 loaded `image-decode.html` through the compiled package import map. WebGL2 backing was 320×240 for a 160×120 logical canvas at DPR2. The browser downloaded the actual 98-byte [2×2 RGBA PNG](rgba2.png), then chose that file through the file picker. `decodeImageBlob` returned 16 bytes: red opaque, transparent black, blue opaque and green opaque. After `setImageAsset`, actual readback/hit was `(30,30)` red/Sprite, `(70,30)` yellow/Back through the transparent image pixel, `(30,70)` blue/Sprite and `(70,70)` green/Sprite. `getImageAsset` returned the same 16 decoded bytes.

In the browser, corrupt PNG returned `INVALID_ASSET`, SVG MIME returned `UNSUPPORTED_FEATURE`, a Blob above 8 MiB returned `ASSET_LIMIT`, and a valid 4097×1 PNG returned `ASSET_LIMIT`. Each result reported `retained true` for canonical Scene, registered bytes, four pixels/hits and generation. The browser downloaded an actual 733-byte [v1 document](saved.json). The live renderer view was moved by 40 logical pixels, changing sampled hits; chooser Open of the saved file staged a fresh canvas/renderer at generation 2 and restored all four original pixels/hits and all 16 asset bytes. The [screenshot](reopened.png) shows that reopened result.

The browser console's only error was the static server's missing `/favicon.ico`; the compiled modules loaded. This is one local Chromium/WebGL2 device observation. It does not establish cross-browser color, EXIF, ICC/HDR, hidden RGB under alpha zero, network loading, caching, animation or general PixiJS Assets behavior.
