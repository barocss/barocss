# @barocss/render-editor

An experimental source-authoritative GPU scene document, pure session/controller, and reusable React workbench. The full shadcn application is `apps/render-editor`. This module uses the public BaroCSS GPU compiler and renderer.

Source animation uses an explicit version1 `gpu-scene` document with original linear translation keys. The exact version0 document remains supported; mixed version1 `mixed-depth` remains a different kind. Enable/Disable animation stages a schema change for complete Apply. `RenderSceneDocument` is the V0/V1 union. Original `animation` tracks refer to exact Source1 object IDs and store Number seconds/XYZ translations. Public `validateRenderSceneAnimationClip` admits those originals; `sampleRenderSceneAnimationSource` uses the actual GPU translation sampler over a derived group-only rig and writes only sampled translations into a display source. Runtime aliases, poses and clocks are not authored data.

The session exposes `draftAnimation`, `animationDirty`, `animationInputInvalid`, `setDraftAnimation` and `setAnimationInputInvalid`. Source, camera and clip form one accepted document/history. Invalid hidden key text blocks all Apply modes and files. Camera-only Apply keeps valid clip drafts separate. Complete source/clip Apply qualifies original references, and removing a tracked object requires its track to be removed first or a precise refusal. Discard restores accepted source, camera and keys. No key sorting, reference repair or ID shortening occurs during admission.

`animationPreview`, `previewAnimation(timeSeconds)` and `cancelAnimationPreview()` present sampled Source through the existing renderer without changing original source, keys, revision or history. Reset restores the accepted base frame before clearing the preview. A retained refusal keeps the last good sample; unavailable presentation keeps CPU authoring and requires recovery. The React timeline owns Play/Pause, caller elapsed time and requestAnimationFrame cleanup. Paused samples remain a preview and require Reset before authoring or File actions. Original key fields retain invalid text across selection and disclosure changes. Save includes original source and keys and excludes sampled poses, playback time and layout. This first animation profile uses linear translation; Source updates can recompile shaders, so no frame-rate guarantee is made.

Source1 transform gizmos edit the selected original object through its actual source. Move uses world XYZ axes. Rotate uses direct front-arc hit testing, with dimmed rear arcs and pointer/focus highlight. No separate XYZ toolbar is required. Nearest visible geometry chooses one axis, which stays captured throughout the gesture. Rotation edits Source Euler X then Y then Z degree fields (gimbal axes, not orthogonal World/Local quaternion rotation). Drag intent follows the projected tangent at the grabbed ring location with bounded pixel sensitivity. Box Scale X/Y/Z changes each actual local size component independently; Rounded Box Size X/Y/Z changes dimensions while its single radius stays fixed. The other shapes retain Uniform scale. Uniform S changes supported dimensions and endpoints together. These Source1 dimension tools do not add a general affine property. Numeric properties remain the fallback for degenerate or unsupported mappings. Public camera/pose services supply widget mappings; a group-only pose rig is not mesh geometry. Live transform preview displays the actual Source renderer update without authoring. Release restores the accepted scene, stages source and applies once; Escape or Cancel restores the accepted frame. One gesture is one history entry, and zero motion is no authored change. Preview state is not serialized.

GPU Scene navigation uses a local viewport camera. Drag Orbit, Shift-drag or Pan, wheel and focused keyboard controls change the real displayed camera without editing source, keys, drafts, scene camera or history. `viewportCamera` is separate from the document; `navigateViewportCamera`, `resetViewportCamera` and `applyViewportCameraToScene` expose this boundary. Outliner selection and authoring remain available after navigation. Source, gizmo, key and playback updates preserve the local view; Open and recovery return to the scene camera. Set scene camera adopts the displayed camera through complete Apply once and retains existing input guards. Save excludes the viewport camera. The legacy explicit `cameraPreview`/Use/Cancel API remains independently supported.

The GPU Scene workbench exposes structured object tools for Source1 Sphere, Box, Cylinder, Capsule, Rounded Box and Torus scenes. Add and Remove stage original source changes. Object properties stage Position, local X/Y/Z Rotation in degrees, type-specific dimensions or endpoints, and opaque color. Whole Apply renders and commits the complete draft; Undo/Redo and version0 files retain original source, IDs and camera. Empty scenes are supported. This broader GPU scene profile is separate from the mixed one-Sphere/one-Surface version1 profile.

`duplicateRenderSceneObjectSource(source, objectId, newId)` creates one independent Source1 primitive from the real compiled effective properties. It copies Position, Euler Rotation, opaque Color and the kind-specific dimensions/endpoints into explicit ID rules. Existing source text, rules, comments, original IDs and original object semantics remain intact. New IDs use the existing ASCII 1..48 policy; Source and object-count budgets remain unchanged. Invalid/missing/colliding IDs are `DOCUMENT_INPUT`; compilation or semantic admission failures are `SOURCE_REFUSED`. The original numeric text is retained. New copy spelling follows the existing numeric writer; original spelling or signed-zero bit copying is not promised.

Duplicate selected and the host Edit command stage source only. The copy becomes selected after complete Apply succeeds. There is no automatic position offset or animation track. Move or edit the copy separately. Source, hidden object/key text, camera and transient-operation guards remain. `onDuplicateCommandChange` optionally exposes the same library-owned command to a host; a null command revokes that binding. Local viewport navigation is not an authored draft.

`inspectRenderSceneObjects`, `editRenderSceneObjectSource`, `addRenderSceneObjectSource` and `removeRenderSceneObjectSource` use the public GPU compiler AST and effective source semantics. No-op edits preserve exact bytes; selected edits preserve unrelated objects and source. The Source session's `objectInputInvalid` and `setDraftObjectSource(string | null)` retain incomplete field text through a global dirty/Apply guard. Camera and selection retain that guard; explicit manual Source, Discard and accepted context changes reset it. Hidden invalid object input also blocks camera-only Apply and file decisions. Universal affine scaling, mesh editing and picking require separate profiles.

The mixed workbench uses one Scene/Projects dock, a central viewport and an Object/Camera inspector. Its optional `projectBrowser` React node is a host-owned navigation slot. Source starts collapsed and opens through Source or Edit source; the real textarea stays mounted. Apply and Discard remain visible without source editing. Problems opens existing diagnostics and correction actions. Panel tabs and bounded pointer/keyboard separators retain field text, complete Apply guards, camera preview and the same canvas/presenter. Local layout state is not authoring and is never serialized. The read-only view orientation uses the actual GPU camera basis; it adds no picking, camera object or geometry gizmo.

```tsx
import {createRenderEditorSession, createRenderEditorController} from '@barocss/render-editor';
import {RenderEditor} from '@barocss/render-editor/react';
import '@barocss/render-editor/style.css';

const session = createRenderEditorSession(originalDocument);
const controller = createRenderEditorController(session);
// Mount in a React host. The host owns menus, routes, files and the session lifetime.
<RenderEditor controller={controller} onError={showError} onAction={handleFileRequest} />;
```

The root imports without React, DOM access, clocks or global listeners. Session setters change draft data. `prepareDraft('source' | 'camera' | 'both')`, `prepareOpen(text)`, `prepareUndo()` and `prepareRedo()` produce immutable session-bound candidates. `commitPrepared(candidate, beforeCommit?)` locks mutations, runs a synchronous callback, and commits only after successful presentation. A headless consumer can omit the callback; CPU acceptance alone does not prove a displayed frame.

The controller accepts an injected `RenderEditorPresenter`. The React `SceneViewport` attaches the actual source1 GPU adapter. `apply`, `open`, `undo`, `redo` return `{ok:true}` or `{ok:false,error}`. `getSnapshot()` tracks `presentedRevision` separately from the session's accepted document revision. A direct headless session commit while attached requires explicit controller recovery before the next visible transaction.

Source Apply calls `SceneRenderer.update`. Camera Apply calls `setCamera`. Combined Open/history uses source update then camera update. On a second-call refusal, the adapter compensates previous source then previous camera and checks framebuffer liveness. Failed recovery/context loss retains CPU authoring and marks presentation unavailable. `recover()` explicitly disposes and mounts a new renderer. There is no new atomic GPU API.

The exact version0 `gpu-scene` document stores `documentId`, `title`, `revision`, `sourceVersion:1`, byte-exact `sceneSource` and the public `MeshCamera` fields. It saves no IR, GLSL or buffers. File input is limited to 262144 UTF-8 bytes, source to 65536 bytes, history to 32 entries and 4 MiB. Plain own enumerable data is required. Unknown fields, unsupported versions, accessors, stale/foreign/forged/reused candidates and invalid source/camera refuse.

Accepted metadata copies real compiler scene name, object IDs/types and declaration ranges. Selecting a row locates its declaration; it is not SDF canvas picking. Complete admitted source1 scenes can add/remove/reorder supported objects. Source and camera drafts remain independent. Undo/Redo uses increasing editor revisions; Open retains the imported revision and starts fresh history. `savedRevision` records an explicitly marked revision or an imported baseline; the host distinguishes file downloads from local workspace opens.

React exports `RenderEditor`, `SourcePanel`, `ObjectPanel`, `CameraPanel`, `DiagnosticsPanel`, `SceneViewport`, and `createSceneViewportPresenter`. `header` and `toolbar` slots take host-owned controls. Optional `onAction` requests New/Open/Save; the module performs no file I/O. Viewport disposal releases owned renderer/listeners/resize observation and preserves caller canvas/DOM. The caller disposes its session.

Source-default main/types/exports use `src`. Complete public `publishConfig` maps root/React JS/declarations and explicit CSS to `dist`. `build:library` emits external-provider ESM, declarations and copied CSS. Public configuration is separate from registry publication.

```sh

pnpm --filter @barocss/render-editor-app build
```

The browser flow starts and closes the actual app's Vite server on `127.0.0.1:52047`. It needs the already installed Playwright CLI/Chrome and a free app port. It saves actual file downloads, opens a saved disk file in a fresh tab, and checks pixels, rejected updates, history, routing and owned cleanup. Unchanged requests reuse the same Vite transform object; a real fixture source edit changes it and appears after reload, then the source is restored. The compiled checkpoint reads transitive published maps separately from source development. No dependency download, packed-consumer or publication step is performed. Native receipts and Integration adoption are recorded in #1047/#1051.

CAD assets/Viewer, qualified materials, Physics and shared-depth SDF+CAD remain later roadmap contracts. See the [Render Editor roadmap](https://github.com/barocss/barocss/wiki/Render-Editor-Product-Roadmap).

## Original-source mixed document foundation (#1092)

`RenderMixedDocumentV1` is an explicit separate `version:1, kind:'mixed-depth'` authoring format for GPU profile `sdf-sphere-native-surface-v0`. It stores original source1 Sphere text and complete original Source0 CAD model text, a declared asset revision/model/Surface selection, camera, color, sampling counts and one explicit mm-to-scene conversion/scene translation. Unrendered native objects remain in the saved source. V0 source editor files and their parser/session remain unchanged. The foundation alone does not open/render this kind; the mixed app is described below.

```ts
import {parseRenderMixedDocument, serializeRenderMixedDocument,
  prepareRenderMixedDocument} from '@barocss/render-editor';

const authored = parseRenderMixedDocument(savedText);
const prepared = prepareRenderMixedDocument(authored);
// Save the document; frame/packet/model/metadata are reconstructed display or query data.
const text = serializeRenderMixedDocument(prepared.document);
```

`copyRenderMixedDocument`, parse and serialize validate schema, original string/byte limits and public camera data; they do not certify source/native/GPU admission. The explicit `prepareRenderMixedDocument` compiles both original sources through public CAD/GPU, qualifies selected original model/Surface IDs, tessellates only that Surface, then calls actual public `prepareMixedDepthFrame`. It returns copied/frozen complete native model and metadata plus the derived frame. Declared asset revision is a host association, not historical content certification. GPU packet shape validation does not certify the original CAD; this host preparation reconstructs it from its actual source each time.

Each source is limited to65536 UTF-8 bytes/code units, the authored file to524288 UTF-8 bytes, sample counts2..17. Exact plain own data is required; unsupported fields/versions, accessors/symbols/sparse/foreign/nonfinite data refuse. The JSON encoder preserves real numeric `-0` and original source strings without a sentinel or source rewriting. `RenderMixedDocumentError` preserves actual provider causes under INPUT/VERSION/BYTES/SOURCE/QUALIFICATION/NATIVE/GPU.

The profile requires exactly one Sphere and one selected Surface, at most289 derived vertices/512 triangles; actual GPU camera-inside/clip/travel/F32 guards apply. Complete native source/weights/UV/IDs remain authoritative. The pure foundation adds no renderer/session/UI. Mixed session and app support are described below; Viewer, CAD feature editing, materials, picking, Physics and additional mixed SDF shapes remain outside this profile. Integrated code availability and integrated validation are separate.

`node apps/render-editor/mixed-document-flow.mjs --output <new-evidence-directory>` exercises ordinary headless source imports, authentic full native source/qualification, real authored file cold reconstruction, copied data and refusals. This is a source/API/file CPU flow, not a mixed framebuffer or app Save/Open receipt. It uses installed tools and current source providers without provider rebuild, alias or packed-reader campaign.

## Camera navigation and a temporary view (#1169)

`deriveRenderCameraInteraction(camera, interaction)` returns an owned frozen camera using public `validateMeshCamera` and `prepareCamera`. Deltas must be finite; CSS dimensions must be finite, positive and at most16384. A finite positive zoom factor above1 moves the eye nearer its target; below1 moves it farther. Lens and clipping fields stay unchanged. Invalid poses are refused by actual camera validation with the original cause; they are not clamped.

Orbit turns the eye around its target through the public view basis, rotating the up vector with it while preserving its magnitude. Horizontal/vertical angles are `-2π×deltaX/width` and `-π×deltaY/height`. Pan shifts eye and target together along the actual right/up basis at target depth. These calculations map host gestures to camera inputs; they add no projection kernel, native geometry change, rendered hit or picking API.

If those drafts or presentation refuse, the accepted authoring/history stays unchanged, with the staged camera retained for correction. A successful Use is one accepted revision/history entry.
