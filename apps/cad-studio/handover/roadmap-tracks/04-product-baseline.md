# First product acceptance baseline — B01–B10

[Current roadmap](../roadmap.md) · [Reference review](05-reference-review.md) · [P0 reliability](01-reliability.md)

## Product target and measurement boundary

Target: an engineer can create a parametric mechanical part, revise it without losing intent, place it in a basic static assembly, issue a drawing and supported exchange file, and reopen the editable work. Manual Studio, existing automation and declarative React must share the owned model, not separate competing geometry implementations.

B01–B10 fix the first product **scope list**, informed by CADCraft/SolidCraft/CadXStudio and our recorded implementation. They do not enumerate every possible CAD capability, replace34 scope rows or certify commercial release. P0-R01–R12 are repair/contract work packages, not ten more product features. Physics, generic advanced geometry, general DWG/BIM/PDM, production processes and held work are excluded from this baseline.

## How a scenario becomes accepted

1. Select its category and freeze the actual Doc(s), support profile, actions/subcase list, expected quantities/tolerances, file consumers and source owners in its decision. A missing accepted input is a gap to resolve, not permission to synthesize a passing substitute.
2. Map retained proofs to each requirement. Mark exact-source reuse eligible, stale/incomplete or absent; preserve custody failures. Re-run only newly affected/uncovered steps with necessary antecedents. Record each required subcase as PASS, FAIL, NOT_RUN or unsupported/HOLD with a reason.
3. Add minimal fixes only after reproduction. Use the required tier, root's own actual Studio flow and appropriate independent numerical/file oracle. No worktree writes during actual Studio and no concurrent heavy jobs.
4. Accept a B scenario only if every frozen required subcase is supported and passes. A deliberately tested typed refusal can pass its refusal requirement; it cannot stand in for a required positive feature. Split a held extension out explicitly rather than silently shrinking the baseline after a failure.
5. Publish aggregate baseline coverage only when all ten scenarios' requirement matrices and retained-evidence adjudication are known. Until then state exactly which scenario/subcases are adjudicated. Even accepted10/10 would mean this first mechanical-CAD baseline, not full CAD, all34 rows or release readiness.

The baseline is a living versioned contract: a new requirement changes the matrix version and denominator explicitly. Maintain implementation availability, UI/consumer evidence and independent numerical authority separately. D521 was the first execution milestone under this plan. D538/B01 and D539/B02 supply adjudicated scenarios at their explicit v1 scopes; next selection follows the current roadmap, not the old initial milestone.
