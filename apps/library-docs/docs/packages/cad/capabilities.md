# Supported CAD shapes and edit chains

Choose a supported input **and** output profile before composing operations. This is the compact capability entry point for the current exact-affine convex part family, not a replacement for the [full CAD requirements](https://github.com/barocss/barocss/issues/503), [API reference](./api) or [other CAD guides](./guides). Issue/API counts are not a completion percentage.

**Evidence snapshot: 2026-10-12.** The adopted source checkpoint is [d71cb7dd](https://github.com/barocss/barocss/commit/d71cb7dd79569aaeb12a8915d28293c4b9801c1c). The separately executed [sketch → cut → edit → reopen recipe](./exact-prism-modeling) deliberately keeps its tested `31b3033f` source pin. Neither source exports nor emitted builds establish npm availability.

**Choosing an authoring interface?** The [CAD text versus JSON/API coverage table](./language#what-can-the-model-language-express-today) identifies what Source0–3 can actually express. In particular, text `@extrude` creates an open Surface; the qualified sketch-to-Solid producer below is a different operation. Mass properties and display meshes are derived results.

## Shapes, operations and refusal boundaries

All native coordinates are millimetres. Complete original source, native geometry, IDs, lineage and exact qualification remain authoritative; triangles and editor views are derived. Source links below pin the actual implementation or executable fixture, not a moving branch.

## Which edit chains have evidence?

- **Executed manual recipe:** pentagonal prism 7168 mm³ → slab remainder 5120 → wider-cut remainder 3328 → v0 serialize/reopen. A separate chamfer on the uncut prism gives 7104 → 7152 mm³ for distance 2 → 1. [Immutable consumer receipt](https://github.com/barocss/barocss/blob/8535d09f2c6c5d5c706e33d3802d595151f41df0/apps/library-docs/evidence/exact-prism-modeling.json)
- **Native serial split:** block → sloped retained half → another plane split, with complete context and new IDs. The serial-split fixture above proves this bounded composition, not every subsequent cut
- **Native v1 edits:** distance-only, tool-width, parent-height and admitted sketch-coordinate updates with full validation and refusal retention. Height 8 → 4 at distance 1 yields parent 3584, retained chamfer 3568 and slab components 1024 + 1536 mm³. Tool edits retain the sibling chamfer; they do not chamfer the cut parts
- **Native serial part v2:** [the actual second-component workflow](./serial-part-v2) now has accepted source/emitted/fresh-process evidence under #1607. At rearX 16/20 and height 8/6, finished second-component volumes are 3064 / 2296 / 3320 / 2488 mm³ with setback 1. Original face/use provenance resolves the edge; generated IDs are outputs
- **Not established:** arbitrary component/edge selection, repeated arbitrary feature chains or a general feature DAG. V2 proves its fixed six-role chain, not those wider operations

## Known counterexamples, not hidden tolerances

At the v1 pin, height 8 → **6** with distance 1 requires wall UV **5/6**, which is not exactly binary64-representable in the existing normalized chart. The edit is refused atomically; an ordinary integer height is not sufficient for admission. An isolated rear X edit **16 → 20** also fails existing exact coplanarity/lift checks. Accepted height 4 and half-scale XY fixtures do not erase these failures. The [native README](https://github.com/barocss/barocss/blob/89459cfdbb2410678e8a5933cc63d75f7c8161b5/packages/barocss-cad/README.md#editable-prism-chamfer-document-v1-1598--par-04--detail-02) retains the correction.

[Explicit coordinate-span producer charts #1603](https://github.com/barocss/barocss/blob/7c81d103605994f218fc5499fb2d66141bc7cca3/packages/barocss-cad/src/xy-affine-sketch-prism.ts) are now adopted, with [source/emitted/cold verification](https://github.com/barocss/barocss/blob/7c81d103605994f218fc5499fb2d66141bc7cca3/examples/cad-nurbs/coordinate-span-prism-verification.json). The earlier a5019338 snapshot marked this work **UNPROVEN**; that historical status is superseded for the explicit producer and v2 profiles only. The accepted height 6/rearX 20 combinations use authored coordinate-span charts and exact-affine admission. A combined rearX 20 / upperX 24 cut still refuses non-binary64 XYZ `80/3`; height 10 with a height-8 tool still refuses incomplete coverage. No implicit chart search, snapping or tolerance repair is promised. Validators establish complete self-consistency, not external source authenticity.
