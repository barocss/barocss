# D336 결과

직접 곡면을 사용하는6개 경로에서 trim 손실을 재현했다. 이제 지원하지 않는 trim 입력은 기존 오류 코드로 거부한다. 새 trim 형상 기능을 추가하지 않았다. 전체08 완료를 뜻하지 않는다.

- 수정 전: 실제 Model6개 경로가 잘못된 성공을 반환했다. 원본 trim 객체는 숨김 상태로 남았다. IGES 실제 재읽기 면적은1200이며, 독립 기준은1100이다. 교차선은 제거한 구간10mm를 통과했다.
- Model: 관련24PASS. 잘못된 trim 컨테이너 검사를 추가한 뒤 집중7PASS. 타입·린트 통과. High 소스 검토에서 조치할 문제 없음. 검토자 런타임은 NOT_RUN.
- 실제 Chrome/WebGPU: 단일 FULL_FLOW PASS. 17개 관찰 상태와6개 거부 동작을 기록했다. 새 알림, 문서·선택 유지, 다운로드 없음이 확인됐다. native 저장·새 Open, Untrim/Reverse, Undo2회·Redo2회가 통과했다.
- 양성 IGES: 의도적으로 Untrim한 곡면2개를 다운로드하고 공개 Kernel 파서로 다시 읽었다. trim 보존 증거는 아니다.
- 별도 solid: keyb1, 부피420, 중심[86,.5,3.5], 이름 유지. 공차1e-7은 이 solid에만 적용한다.

원본 표시 메시의 면적1100.081380233은 독립 기준1100과 다르다. 메시 정밀도를 수정했다는 주장은 없다. Studio thicken은 NOT_PROVEN이다. 전체 제품 테스트, 성능, 원격 CI, 릴리스는 수락하지 않았다. D335 Kernel2229PASS/6SKIP은 이전 기준이며 이번 실행이 아니다.
