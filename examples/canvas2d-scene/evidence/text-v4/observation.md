# C2D-07 bounded host text observation

2026-10-08. Native parent `83570bcb` contains #691 glyph runs and #702 command history. Branch `codex/canvas2d-704`. This is an example-host editing surface; the Canvas2D renderer remains a glyph-quad consumer. No package publication, product push or merged-head claim.

## Frozen text and ownership policy

- The accepted character set is uppercase `H`, `I` and ASCII space, 1–6 UTF-16 units with at least one visible H/I. Every accepted character occupies five top-to-bottom RGBA8 atlas columns; spaces are transparent. The fixed host bitmap for H/I uses ink `[20,32,56,255]`, 40×56 rendered glyphs, 48 logical-pixel advance, baseline 120, and an `EditableText` v4 run. The DOM input owns caret and selection; Apply is the only commit action. No browser font rasterization, multilingual shaping, BiDi, line layout or IME conformance is claimed.
- Every accepted edit creates a copied `AtlasN` image asset and explicit glyph quads, registers the asset, then commits through existing `SceneHistory`. Old atlas IDs remain registered for Undo/Redo; the demo caps itself at 16 registered atlases per open file and eight history entries. The v1 document saves only the referenced atlas. Cold Open validates/hashes the file and host glyph policy on a fresh canvas, then replaces the visible canvas and starts a one-entry history. Failed commands and files keep the prior accepted text, frame and history cursor.
- Node 22.22.0 affected `pnpm --dir packages/barocss-canvas2d build:library` exited 0; existing main bundle 85.4 KiB. `node examples/canvas2d-scene/text-probe.mjs`, `history-probe.mjs` and `document-probe.mjs` exited 0. The new probe checks atlas bytes, space transparency, UTF-16 offsets, Scene v4 JSON, unsupported text, actual saved file asset bytes, corrupt digest and command Undo/Redo. `git diff --check` exited 0.

## Actual Chromium flow

- URL: `http://127.0.0.1:57011/examples/canvas2d-scene/text-v4.html`. Initial `HI`/`Atlas1` put dark glyph pixels `[20,32,56,255]` at `(35,70)` and `(82,70)`, both hit `EditableText`; `(130,70)` was white/`Paper`.
- Filling the real DOM input with `H I` placed its caret at UTF-16 offset 3. Apply generated `Atlas2` (15×7, 420 RGBA bytes), with glyph ranges `[0,1]` and `[2,3]`, and committed history position 1/length 2. `(82,70)` became white/`Paper`; `(130,70)` became dark/`EditableText`. DOM keyboard `End`, then `Shift+ArrowLeft` selected offsets 2–3. Undo restored `HI`/`Atlas1`, the prior pixel/hit and history cursor 0/2. Redo restored `H I`/`Atlas2`, dark `(130,70)` and cursor 1/2.
- Applying unsupported `Hi` returned `UNSUPPORTED_FEATURE` and restored the accepted DOM value `H I`. A missing atlas command returned `INVALID_ASSET: missing glyph atlas MissingAtlas`. A 1×1 replacement of in-use `Atlas2` returned `INVALID_ASSET: glyph crop exceeds atlas Atlas2`. Each refusal retained the exact visible canvas, accepted text, history cursor, 420-byte prior asset, dark `(130,70)` pixel and `EditableText` hit. [Refusal screenshot](text-refusal.png) shows the last case.
- Browser Save downloaded the actual [1,543-byte document](text-document.json) containing `H I` and the referenced `Atlas2` bytes. After editing back to `HI`/`Atlas3`, uploading that saved file created a new canvas and restored `H I`, `Atlas2`, three representative pixels/hits and DOM input; history restarted at 0/1. [Opened screenshot](text-opened.png) shows the result. Uploading the [corrupt-digest file](text-corrupt.json) returned `INVALID_ASSET: asset Atlas2 SHA-256 mismatch` and retained that exact accepted canvas, text, cursor, pixel and hit.
- Browser console contained only the unrelated missing `favicon.ico` 404; no runtime warning was observed. The browser and server were closed.

This establishes one bounded Chromium host flow and a fixed two-letter Latin bitmap policy. It does not establish general text editing, font compatibility, accessibility certification or IME behavior.
