## Contract, build and probe

- `exportCanvasDocumentPNG` hashes and validates a canonical v1 document before requesting a fresh host canvas. It renders at a declared logical size/DPR, asks the browser to encode `image/png`, returns Blob and logical/backing dimensions, then disposes the temporary renderer. It does not replace the host canvas. Browser PNG serialization decides final color encoding; the observed file is 8-bit RGBA with top-to-bottom rows. Opaque pixel samples are checked; hidden RGB under zero alpha and cross-browser color or byte identity are not asserted.
- `exportSceneSVG` admits only validated v5 groups and M/L/Q/C/Z paths with contiguous sibling layers, representable transforms, byte-grid RGB, explicit fill/stroke alpha, nonzero/evenodd fill and butt/bevel stroke. Success returns SVG and source ID map. Refusal returns structured `{nodeId,code,feature}` diagnostics and no partial SVG. Frames, clips, rects, lines, images, glyph runs and unsupported paint are refused. Reimport adds the importer viewport wrapper, so authored Scene JSON is not round-tripped byte-for-byte.

## Actual browser files and pixels

- URL: `http://127.0.0.1:57010/examples/canvas2d-scene/export-v1.html`. Source: existing real [5,687-byte v4 document](../document-v1/scene-and-assets.json) with image and glyph atlas assets. Visible source pixels at logical `(460,250)`, `(552,253)` and `(335,250)` were `[255,0,0,255]`, `[20,32,56,255]` and `[51,83,97,255]`.
- Exported [PNG](canvas-document.png) is 69,399 bytes, `1600×960`, 8-bit RGBA at logical `800×480`, DPR2. The browser reopened that actual downloaded file with `createImageBitmap`; all three pixel samples matched the live WebGL canvas. A corrupt-digest document returned `INVALID_ASSET: asset GlyphHI SHA-256 mismatch` before calling the canvas factory (`canvasCreated:0`); the same live raster canvas and GlyphHI pixel remained.
- Exported [SVG](canvas-vector.svg) is 516 bytes with four source IDs (`VectorBoard`, `Artwork`, `Shape`, `Curve`). The original vector scene had Shape `(40,40)` `[51,102,204,255]`/`Shape`, hole `(90,85)` `[0,0,0,0]`/no hit, and Curve `(175,43)` `[34,51,68,255]`/`Curve`. Uploading the actual downloaded SVG through the existing bounded importer created a fresh canvas and retained all three samples and path IDs.
- Vector export of the v4 document refused with structured diagnostics naming `CroppedChecker`/`RGBAQuadrants` images and `GlyphHI` glyph run, among other unsupported nodes. The exact previously accepted vector and raster canvas objects, Shape pixel/hit and GlyphHI pixel stayed unchanged. [Final screenshot](export-final.png) shows both live canvases and the refusal. The final browser reload had zero console errors or warnings; an earlier load had a favicon 404 and a readback performance warning, both unrelated to the export semantics.

This establishes one bounded Chromium file flow. It does not establish general SVG export, arbitrary native vector editability, ICC/P3/HDR accuracy, PDF/print output or other browser/device support.
