# Public ticker compiled-consumer observation

Issue: https://github.com/barocss/barocss/issues/756. Exact native parent: locally integrated #754 `1da3e7e0ab9e28689db6b7dd6458174783f25405`. The first implementation and browser flow used a clean draft branch from native #754 while Integration finished. The native child was then rebased onto the integrated parent and verified again before handoff. This is Execute evidence before #756 Integration.

Node 22.22.0 `pnpm --filter @barocss/canvas2d build:library` passed on the integrated parent with compiled public JavaScript (106.4 KiB) and declarations. `tsc -p packages/barocss-canvas2d/consumer/tsconfig.json` passed with the fourth package-local consumer. `node examples/canvas2d-scene/ticker-probe.mjs` passed a fake scheduler with frame 1 zero delta, 16-ms and 200-ms elapsed intervals, 100-ms capped delta, descending priority and stable equal-priority order, idempotent start/stop/dispose and duplicate unsubscribe, canceled late callback, stop/restart within a callback with one pending frame, listener-list snapshot under unsubscribe/add, stop-versus-dispose during a frame, bad/backward timestamps, listener cap 128, malformed registration and exception stop. Unavailable default scheduling refused with `UNSUPPORTED_FEATURE`; a synchronous scheduler callback refused with `INVALID_SCENE`; changing an injected scheduler method after construction did not replace the validated callback. The prior pointer and display-tree reconstruction probes also passed on this parent; the commit delta whitespace check was clear.

Opened `http://127.0.0.1:57021/packages/barocss-canvas2d/consumer/ticker.html` in Headless Chrome 155. The import map used only compiled `@barocss/canvas2d`. The Scene v6 sprite used one copied 2×2 RGBA8 asset and a 160×100 logical canvas at DPR2 (320×200 backing). Before start, sprite x=20: (30,30) was `[255,0,0,255]`/Moving and (70,30) transparent/null. The host then started the default browser ticker. Frame 1 reported `elapsedMS=0`, `deltaMS=0`; frame 2 reported `16.634` ms; frame 3 reported `16.700` ms. Its callback used capped `deltaMS` to move the sprite, explicitly submitted `tree.snapshot()` and rendered, and stopped at x=60. At that point (30,30) was transparent/null, (70,30) `[255,0,0,255]`/Moving, and accepted Scene JSON equaled the tree snapshot.

After an 80-ms browser wait, the exact observed state, frame history, pixels and hits remained unchanged. Resume delivered frame 4 with both deltas 0, left x=60 and stopped again. Dispose left `running=false`; a later `start()` returned `DISPOSED`. The final integrated-parent browser run at port 57023 again moved x=20→60 in three frames, returned the same before/after pixel and hit samples and canonical Scene equality, and resumed with frame 4 delta 0. The [full-page screenshot](stopped-after-resume.png) is from that final run. The only console error was the static server's missing `/favicon.ico`; no module-load error or warning appeared. Both browser sessions and static servers were closed.

This single local browser/GPU run does not establish a fixed FPS, broad browser support, visibility policy, automatic render loop or PixiJS ticker parity. The host owns the renderer, Scene submission and canvas lifecycle.
