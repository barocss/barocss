## Qualification

- **PASS** — A new dyadic triangle has source determinant −2¹²¹. Its three distinct encoded vertices are exactly collinear, although the binary64 calculation on those encoded vertices yields +2¹⁴⁹. The public writer returns `STL_FLOAT32_COLLAPSE`. The nearest-even overflow midpoint returns `STL_FLOAT32_RANGE` for either sign. One binary64 step below the positive midpoint still records the largest finite Float32. An independent Sol High check verified the new literals and both existing normal policies.
- **PASS** — An expanded read-only scan checked 56 existing native part fixtures and 37 existing fuzz fixtures. Of 93 documents, 91 evaluated and two had evaluation refusals. All 102 evaluated output bodies produced a nonempty display tessellation at eight segments per quarter. Automatic native STL produced bytes for 100 bodies and typed precision refusals for two. There was no non-precision availability candidate in this scan. This scan uses the native package directly, so it is separate from the earlier 35-body Model scan.
- **PASS** — Current desktop Chrome WebGPU replay of the real Worker path, six states and 329 frozen inputs. Automatic and Fine 32 returned the first body's bytes and the second body's precision refusal. No STL or sidecar reached the download boundary. The ordinary control produced both 684-byte payloads, which matched the actual Worker bytes and passed the independent byte oracle. Native project Save and fresh Open retained the exact document.
- **PASS** — Current D682 desktop replay, nine states and five independent reads. Actual late replies after Cancel, Open and Redo created no stale output. The controlled unavailable reply reached the valid display fallback. The touching-lump path retained two STL payloads and a source record. Focused CAD 6/6, Model 11/11 and Studio 41/41, driver syntax and diff check passed.
- **FAIL** — None in the current scope. The original D681 reproduction remains the evidence for the former serialization failure.
- **NOT_RUN** — A genuine unavailable-result Worker response from an otherwise fresh, displayable body. The controlled response does not satisfy that condition, so #2425 remains open. Full suites, mobile, actual browser download and third-party slicer were also not run.

Run with Node 22.19.0, existing Chrome and Playwright, and the serial heavy gate. The external scan reads sorted JSON inputs under `robustness/corpus/parts` and `robustness/corpus/fuzz`, uses `input.partDocument` when present, then calls `evaluateCadPart`, `tessellateBrep` at eight segments per quarter and default `exportStl` on the same output.
