# @barocss/physics

A small, renderer-neutral fixed-step 3D dynamics prototype. It simulates dynamic spheres, oriented boxes and capsules with gravity, one-step linear/angular commands, normal contact, bounded point friction and limited fixed/hinge joints. It includes opt-in fast sphere CCD for a restricted static-box world. The admitted contact matrix supports sphere/sphere, sphere/oriented-box, sphere/capsule and oriented-box/oriented-box. It does not simulate capsule/box or capsule/capsule pairs, dynamic/dynamic joints or meshes.

The public entry is `src/index.ts`. Types and internal body records are in `types.ts`; input admission is in `validation.ts`; vectors, quaternions and inertia transforms are in `math.ts`; primitive collision and contact response are in `collision.ts`; joint parsing/projection is in `joints.ts`; fast sphere sweep is in `ccd.ts`; optional broad-phase bounds are in `broadphase.ts`; and fixed-step world state is in `world.ts`. `limits.ts` holds shared bounds. The public package export still resolves to compiled `dist/index.js` and its declarations.

The optional `@barocss/physics/cad-proxy` subpath admits one selected BaroCAD sourceVersion 0 native Surface from an exact source string. Its modules separate native admission, input validation, copied binding types and Viewer pose mapping. It depends on the public `@barocss/cad` compiler. `admitCadSurfaceProxy(source, request)` creates a qualified `part:<model>.<surface>` or `fixture:<model>.<surface>` Physics body from the original Surface control-net bounds in right-handed XYZ millimetres. A sphere encloses the control-net AABB; a box uses its axis-aligned half-spans plus a declared minimum half-extent. The result reports the original IDs, source revision, source center and a shape-loss label. Native rational Surface weights are positive under the CAD compiler profile, so the control net is a conservative envelope; this is not exact Surface collision. Dynamic bodies need explicit mass and may declare a starting offset. Body lengths convert by 0.001 to metres. `assertCadProxyCurrent` compares both the complete source string and caller revision. A change throws `STALE_SOURCE` until explicit re-admission. `cadProxyPose` checks that binding and maps an accepted Physics body pose back to Viewer millimetres, including rotation about the source center. The host owns world replacement and Viewer frame application. See [PHYS-10 #773](https://github.com/barocss/barocss/issues/773#issuecomment-6060408936) and the [native Viewer consumer](../../examples/physics-cad-scene/README.md).

The optional `@barocss/physics/replay` subpath saves an admitted scene and accepted fixed-step command log. `createPhysicsScene(world,{revision,sourceRevision})` copies and validates a version 1 scene; use `sourceRevision:null` for a scene without a CAD source. `createPhysicsReplaySession(scene)` owns a world with `step(commands?)`, `getState()`, `getScene()`, `saveSnapshot()` and `dispose()`. A saved version 1 snapshot includes that scene, one command frame per accepted step and the complete final state. `restorePhysicsReplaySession(snapshot,expectedScene)` checks exact scene/config and source revision identity, replays in a new world, and compares the final state within 1e-12 absolute/relative numeric tolerance. Changed revisions use `STALE_SNAPSHOT`; damaged or unsupported data uses `INVALID_SNAPSHOT`. Input and output are copied JSON-compatible data; object key insertion order does not change scene identity. The profile admits at most 512 recorded steps, 4096 total commands, a 128 Ki-code-unit scene and a 1 Mi-code-unit snapshot. It does not import arbitrary body state, migrate old versions or promise bitwise cross-platform results. See [PHYS-11 #774](https://github.com/barocss/barocss/issues/774#issuecomment-6060601264).

The host owns time and rendering. Physics uses metres, kilograms and seconds. Convert Viewer/CAD millimetres at the host boundary.

```ts
import { createPhysicsWorld } from '@barocss/physics';

const dt = 1 / 120;
const world = createPhysicsWorld({
  fixedStepSeconds: dt,
  gravityMps2: [0, -9.81, 0],
  bodies: [
    { id: 'part:ball', kind: 'dynamic', shape: { kind: 'sphere', radiusM: 0.15 },
      positionM: [0, 2, 0], velocityMps: [0, 0, 0], massKg: 1, restitution: 0.25 },
    { id: 'fixture:floor', kind: 'static', shape: { kind: 'box', halfExtentsM: [1, 0.2, 1] },
      positionM: [0, 0.2, 0], restitution: 0.25 },
  ],
});

const state = world.step(dt); // One caller-requested fixed step, no hidden clock.
console.log(state.bodies, state.contacts);
world.step(dt, [{ kind: 'force', bodyId: 'part:ball', forceN: [0, 2, 0] }]);
world.step(dt, [{ kind: 'impulse', bodyId: 'part:ball', impulseNs: [0, 0.5, 0] }]);
world.dispose();
```

`step(dt, commands)` accepts at most 64 dense, plain-object commands per step: `{kind:'force',bodyId,forceN}`, `{kind:'impulse',bodyId,impulseNs}`, `{kind:'torque',bodyId,torqueNm}`, `{kind:'angularImpulse',bodyId,angularImpulseNms}`, or `{kind:'kinematicTarget',bodyId,positionM}`. Each body may receive one command of each applicable kind per step. Force and torque act for one step; impulses change velocity once. A kinematic body has `kind:'kinematic'`, a sphere or box shape, position and restitution but no mass or input velocity. A target is an absolute metre position for this step; the reported velocity is target movement divided by `dt`. Without a new target it holds position and reports zero velocity. Only dynamic bodies receive force, impulse, torque or angular impulse. Kinematic bodies contact dynamic spheres but do not respond to impulses. Static/kinematic pairs are not reported.

Commands are validated before a candidate step. Dynamic integration applies impulse, then gravity and force, then position; collision resolution follows. Input order does not change the result. `getState()` and `step()` return copies. A failed step leaves the world at its last accepted state.

Dynamic bodies have an optional local-to-world `orientation: [x,y,z,w]` quaternion and `angularVelocityRadps: [x,y,z]`, both in the right-handed world frame. The defaults are identity and zero. Static/kinematic bodies can declare a fixed orientation but do not rotate during a step. The initial quaternion must have unit norm within 1e-6 and is normalized on admission. Sphere inertia is `2/5 × massKg × radiusM²`; an optional positive `inertiaKgM2` scalar overrides it for spheres only. A solid box uses local diagonal inertia `massKg/3 × [hy²+hz²,hx²+hz²,hx²+hy²]`. A capsule uses a labelled isotropic proxy inertia `2/5 × massKg × (radiusM+halfLengthM)²`. Every body state reports copied orientation and angular velocity; a dynamic body reports its scalar or diagonal inertia. World-frame torque and angular impulse use the orientation-transformed inverse inertia. The next angular velocity sets an axis-angle delta for this step. Left multiplication applies that delta in world coordinates, then the quaternion is normalized. Angular speed components are limited to ±1000 rad/s and angular displacement to 10 radians per step. See [PHYS-04 #767](https://github.com/barocss/barocss/issues/767#issuecomment-6058865060) and [PHYS-05 #768](https://github.com/barocss/barocss/issues/768#issuecomment-6058939158) for frozen fixtures and exclusions.

A capsule's segment lies on its local Y axis from `-halfLengthM` to `+halfLengthM`, with radius `radiusM` around it. All shape lengths are 0.0001–1000 m. Only these pair families are admitted: sphere/sphere, sphere/oriented-box, sphere/capsule and oriented-box/oriented-box. An eligible capsule/box or capsule/capsule pair refuses world creation with `INVALID_CONFIG`, even when initially separated. Box/box uses a deterministic 15-axis separating-axis check and one approximate support-midpoint contact point. Contact state reports a copied world-metre `pointM`. The solver uses velocity at that point, including `ω×r`, and applies equal/opposite linear and angular normal impulses. Position correction remains translational. This is a one-point manifold and does not establish stacked-box stability or exact compound-capsule inertia. Sensors use the same admitted shape pairs without impulse. Sphere overlap and ray queries now read oriented boxes and capsules as well.

Any body may declare optional `friction:{static,dynamic}` coefficients with `0 <= dynamic <= static <= 2`; both default to zero. A pair combines matching coefficients by geometric mean. After each normal impulse, the solver evaluates tangential velocity at the point, including angular velocity. It cancels slip when the required impulse fits within `μ_static × normalImpulse`; otherwise it applies at most `μ_dynamic × normalImpulse` opposite slip. Each physical contact reports a copied, accumulated world-vector `tangentImpulseNs`. There is no impulse cache, warm start or persistent static constraint. The fixed sphere stack probe establishes only its recorded 240-step drift/penetration bounds. See [PHYS-06 #769](https://github.com/barocss/barocss/issues/769#issuecomment-6059055828) for the frozen fixture and limits.

Optional `joints` connect one static/kinematic A body to one uniquely jointed dynamic B body. At most eight dense fixed/hinge records use qualified IDs and body-local `anchorALocalM`/`anchorBLocalM` in metres; the initial world anchors must coincide within 1e-6 m. A fixed joint preserves the initial relative orientation and common anchor. A hinge declares a unit `axisWorld` and a `limitRad:[min,max]` within ±π/2 including zero. It allows only signed twist about that axis from B's initial orientation and clamps at the limits. Joint projection runs after each contact pass; a connected A/B collision pair is disabled. State reports copied per-step `joints` with linear and angular reaction impulses, plus hinge angle. Reactions are the dynamic B velocity corrections caused by this bounded projection solver. They are not certified mechanical loads. There are no motors, dynamic/dynamic joints, cycles or CAD-authored assembly constraints. See [PHYS-07 #770](https://github.com/barocss/barocss/issues/770#issuecomment-6059121440) for the exact first-profile contract.

Set `ccd:true` on a dynamic sphere to prevent it from crossing a thin static box in one step. This opt-in profile admits exactly one dynamic sphere, 1–8 static nonsensor oriented boxes, and no joints or other bodies. Other CCD configurations refuse world creation with `INVALID_CONFIG`; omitted `ccd` keeps the discrete solver. The sphere center sweeps through each box-local axis-aligned bound expanded by its radius. The earliest entry fraction wins, with fixture ID breaking equal-fraction ties. The candidate stops at the entry point with a 1e-9 m inward offset so the discrete contact solver can respond. It does not integrate the remaining fraction of the step. `state.ccdHits` contains a copied `{bodyId,fixtureId,toiFraction,normalFixtureToBody}` record for a swept hit, or an empty array. An initial center inside an expanded box uses the discrete solver. Expanded-box corners can conservatively report a hit before exact sphere/box contact. This profile does not cover moving fixtures, sphere/sphere sweeps, multiple dynamic bodies or general continuous collision detection. See [PHYS-08 #771](https://github.com/barocss/barocss/issues/771#issuecomment-6059234992) for the frozen contract.

Optional `broadPhase:'aabb'` filters the existing eligible pair list before narrow-phase detection. Omit it for the original direct pair path. Bounds enclose spheres by radius, oriented boxes by projected half-extents, and oriented capsules by radius plus projected local-Y half-segment. They are updated from each moving body at the start of every solver pass and immediately after its contact correction; static bounds are reused during that step. Intervals overlap inclusively with 1e-9 m slack. `state.pairStats` is a copied per-step `{eligiblePairs,candidatePairs,aabbTests}` count across eight passes. Direct mode has candidatePairs equal to eligiblePairs and zero AABB tests. AABB mode reports one test for each eligible pair; candidatePairs counts narrow-phase calls. The initial state has zeros, and failed steps retain the prior counts. The fixed 32-body/120-step compiled fixture reduced candidate calls from 29,760 to 960 with matching recorded contacts and poses. Its one-machine wall time and heap-use change are observations, not general performance or allocation guarantees. The direct option remains available for contact cascades outside that fixture. See [PHYS-09 #772](https://github.com/barocss/barocss/issues/772#issuecomment-6060293632) for the frozen contract.

`state.events` reports `begin`, `stay` and `end` for the last accepted step. Events carry sorted body IDs and `kind:'contact'|'sensor'`. A static or kinematic collider can use `sensor:true`: it reports overlap events with a dynamic sphere but produces no physical contact, impulse or position correction. Initial overlap begins on the first step. The array is copied with state and is retained after a failed step.

`world.overlapSphere({centerM,radiusM,includeSensors?})` returns lexically sorted body IDs. `world.raycast({originM,direction,maxDistanceM,includeSensors?})` returns the nearest `{bodyId,distanceM}` or `null`; direction must be unit length within 1e-9. A ray starting inside a shape reports distance zero. Both queries read the last accepted state; they do not advance the world. Sensor inclusion defaults to true. Query positions are within ±10000 m, radius is 0.0001–1000 m, and ray distance is 0.0001–10000 m. Spheres, oriented boxes and capsules are admitted. Invalid queries use `INVALID_QUERY` and keep accepted state. See [PHYS-03 #766](https://github.com/barocss/barocss/issues/766#issuecomment-6058738723) for the original event and query rules.

`PhysicsError.code` identifies `INVALID_CONFIG`, `INVALID_STEP`, `INVALID_COMMAND`, `INVALID_QUERY`, `INVALID_SNAPSHOT`, `STALE_SOURCE`, `STALE_SNAPSHOT`, `WORLD_LIMIT`, `NUMERIC_LIMIT` or `DISPOSED`.

Limits: 1–32 bodies, at least one dynamic sphere, 3600 steps, fixed step 1/240–1/30 s. Each position component is within ±10000 m, velocity and gravity components within ±1000 m/s, mass 0.000001–1000000 kg, sphere radius and box half extents 0.0001–1000 m, restitution 0–1. Force and torque components are within ±1000000 N or N·m; linear and angular impulse components are within ±100000 N·s or N·m·s. One step refuses movement or measured penetration above 10 m. Body IDs are unique ASCII identifiers, up to 64 characters, starting with a letter. Contact pairs have ascending IDs; `normalAtoB` points from A to B. See [Issue #751](https://github.com/barocss/barocss/issues/751) for v0 and [PHYS-02 #765](https://github.com/barocss/barocss/issues/765#issuecomment-6058662978) for linear control.
