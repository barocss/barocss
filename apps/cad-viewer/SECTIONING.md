# 화면 절단 계약

상태: **설계, 미구현**. 이 문서는 5.2의 첫 구현 범위를 정한다.

화면 절단은 표시 메시의 일부를 숨긴다. 원본 CAD 형상을 바꾸지 않는다.
교차 곡선, 닫힌 단면, 단면 면적, 체적 또는 제조 공차를 계산하지 않는다.
UI와 문서에서는 이 기능을 **화면 절단**으로 부른다. CAD 단면 결과로
표시하지 않는다.

## 범위와 좌표

- 한 번에 평면 하나를 사용한다. 평면은 켜거나 끌 수 있다.
- 평면은 `{ normal: [x, y, z], offsetMM }`으로 입력한다. `normal`은 유한한
  영이 아닌 벡터이고 `offsetMM`은 유한한 mm 값이다.
- SDK는 법선을 단위 벡터로 정규화하고 offset도 같은 길이로 나눈다.
  정규화 후 평면의 유지 영역은 `dot(normal, pointMM) >= offsetMM`이다.
  평면 위는 유지한다. 잘못된 수나 정규화할 수 없는 값은 거부한다.
- 문서는 원본의 authored XYZ/mm 좌표를 사용한다. 조립품은 각 인스턴스의
  원본 점에 조립 배치를 적용한 assembly XYZ/mm 좌표를 사용한다. 따라서
  같은 원본의 서로 다른 인스턴스도 각자의 배치에서 절단한다.
- 기존 Viewer의 `authored-xyz-matches-rhyup` 표시 가정을 따른다. 새로운
  축 변환이나 원본 geometry 변환을 하지 않는다. GPU 표시 좌표에는 기존
  `mmToSceneUnit`을 한 번만 적용한다. 평면의 정규화된 offset도 같은
  양의 scale을 한 번 적용한다.
- 현재 입장한 Surface와 Curve의 표시를 절단한다. 숨긴 항목은 기존처럼
  숨긴 상태로 둔다. 처음 구현에서 임의의 항목별 제외, 다중 평면과
  cutout은 지원하지 않는다.

## 화면, 선택과 투영

GPU core의 clip plane은 표시를 위한 출발점이다. Viewer SDK가 평면을
검증하고 소유해야 한다. 앱이 Presenter의 내부 core를 직접 변경하지 않는다.

- `pickGeometry`는 잘려 보이지 않는 Surface와 Curve를 선택하지 않는다.
  잘린 앞쪽 교차가 있으면 그 뒤의 유지 영역 후보도 검사한다. Curve는
  평면을 가로지르는 segment의 유지 부분만 대상으로 한다. 단순히 첫 hit나
  segment의 양 끝만 검사하는 방식은 충분하지 않다.
- `projectNativePoint`와 측정 표시점은 절단된 쪽을 표시하지 않는다.
  한 점이 표시되지 않으면 화면에서 두 점을 잇는 선도 표시하지 않는다.
  기존 원본 좌표의 거리값은 절단으로 다시 계산하거나 변경하지 않는다.
- 화면 hit는 기존처럼 표시 메시 기반의 근사 결과다. GPU의 Float32 변환,
  경계 픽셀과 CPU 계산의 차이를 검사한다. 절단 평면 부근에서 양쪽 판정이
  불확실하면 잘린 점을 확정 hit로 반환하지 않는 정책과 허용 범위를 SDK
  테스트에서 고정한다. 어떤 플랫폼에서도 비트 단위로 픽셀이 일치한다고
  주장하지 않는다.
- 투영은 기존과 같이 가림 여부를 검사하지 않는다. 절단을 통과한 점이라도
  다른 면 뒤에 있을 수 있다. 화면 위치를 CAD 교차점으로 취급하지 않는다.
- cap은 처음 범위에서 표시하지 않는다. 열린 Surface와 Curve를 닫힌
  솔리드로 가정하지 않는다. 이후 GPU cap을 쓰더라도 그것은 화면 채우기이며
  원본 CAD 면이나 닫힌 단면 인증이 아니다. 현재 GPU clip의 cap을 끄는 공개
  경로를 확인하거나 GPU 계약을 확장하기 전에는 이 조건을 충족했다고 보지 않는다.

## 수명과 저장

- 절단은 현재 세션의 표시 상태다. 기본값은 꺼짐이다. 파일을 닫거나 새
  원본을 성공적으로 입장하면 꺼진다. 실패하거나 취소한 원본 교체는 기존
  평면과 장면을 유지한다.
- 첫 구현의 리뷰 파일과 이름 있는 뷰는 평면을 저장하지 않는다. 기존
  파일 형식과 호환한다. 리뷰 또는 이름 있는 뷰를 복원해도 현재 세션의
  평면은 유지된다. 저장된 리뷰가 절단 평면을 복원한다고 표시하지 않는다.
- PNG는 캡처 시 실제 절단된 화면을 담는다. 측정 표시 PNG도 같은 절단
  판정을 적용한다. 캡처 시작 후 평면이 변경되면 결과를 버리고 다시
  내보내도록 한다. 평면을 바꿨다가 되돌린 경우도 generation으로 감지한다.
- 원본 검사는 기존 source hash, revision과 reference를 따른다. 화면
  절단은 이를 대체하거나 원본 정보에 추가하지 않는다.

## 실패와 의존성

- 잘못된 평면, 지원하지 않는 Viewer 상태 또는 동기 Presenter 실패는 기존
  평면, 카메라, 표시/선택, 측정, 원본 및 저장 뷰를 유지해야 한다.
  기존 화면을 복구하지 못하면 오류를 보고한다. GPU 장치 손실 뒤 픽셀
  복구까지 보장하지 않는다.
- 공개 Viewer 계약은 현재 평면의 복사본과 설정/해제를 제공해야 한다.
  입력 객체와 반환값을 바꿔도 내부 상태가 바뀌면 안 된다. dispose 뒤에는
  요청을 거부한다.
- GPU core의 현재 clip은 표시와 GPU pick을 지원한다. Viewer는 별도의 CPU
  pick과 투영에도 같은 평면 및 조립 pose를 적용해야 한다. Renderer 설정만
  전달해서 이 계약이 완성되었다고 판단하지 않는다.
- SDK clear, 새 문서/조립품 입장, 가시성 변경과 장치 이벤트의 순서 및
  실패 복구를 확인한다. 재생성 이벤트만으로 화면 복구 완료를 표시하지
  않는다.

## 검증 조건

1. CPU 테스트에서 축 방향과 기울어진 평면, 경계 양쪽, 부호가 반대인
   법선, 단위 변환, invalid 값과 입력/반환값의 독립성을 검사한다.
2. 서로 다른 배치의 동일 부품 인스턴스와 문서 Surface·Curve를 사용해
   화면 절단, CPU pick, 원본 점 투영과 선 segment 잘림의 판정이 일치하는지
   검사한다. 앞의 잘린 hit 뒤에 유지되는 hit가 있는 경우도 포함한다.
3. 평면을 바꿔도 원본 점과 거리값이 바뀌지 않는지, 실패와 취소가 이전
   상태를 보존하는지, 닫기/새 원본 성공 시 평면이 꺼지는지 검사한다.
4. 기존 리뷰와 이름 있는 뷰의 읽기/저장 호환, 세션 평면 유지 정책, PNG
   생성 중 평면 변경에 따른 오래된 캡처 취소를 검사한다.
5. 실제 WebGPU 브라우저에서 문서와 조립품의 절단 전후 화면, 경계 부근
   선택, 측정 표시와 PNG를 확인하고 이미지를 저장한다. CPU 대역 presenter,
   합성 fixture 및 실제 사용자가 제공한 파일의 증거는 각각 구분한다.
   장치 손실 복구와 모든 모델에 대한 CAD 정확도는 별도 검증 대상이다.
