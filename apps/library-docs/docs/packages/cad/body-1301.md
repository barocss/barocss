## Two public API signatures

These signatures belong to the CAD1301 profile:

```ts
buildQualifiedTranslatedStripBody(
  base: TranslatedSurfaceBaseFaceResult,
  ends: TranslatedSurfaceEndFacesResult,
  volume: TranslatedSurfaceStripVolumeResult,
  options: QualifiedTranslatedStripBodyOptions,
): QualifiedTranslatedStripBodyResult

validateQualifiedTranslatedStripBody(
  result: QualifiedTranslatedStripBodyResult,
): QualifiedTranslatedStripBodyReport
```

The constructor returns the complete copied result. The validator reconstructs the parents, source models, topology, material proof and native endpoint observations, compares the complete result, then returns a copied **report**. It does not return an edited Body or adopt an unchecked report.

Four named result/option types are public: `QualifiedTranslatedStripBodyOptions`, `QualifiedTranslatedStripBodyEdge`, `QualifiedTranslatedStripBodyReport` and `QualifiedTranslatedStripBodyResult`. The root also exports `QualifiedTranslatedStripBodyError` and the `QualifiedTranslatedStripBodyDiagnosticCode` value/type. The private material-proof implementation is not a public entry.

### Call the APIs inside the compiled profile

The CLI supplies the complete request and sets up the compiled public entry. This module shows its API operation; run it only in that new profile, not against the older workspace/source runner:

```js
import {
  buildQualifiedTranslatedStripBody,
  validateQualifiedTranslatedStripBody,
} from '@barocss/cad';

export function buildBodyFromCompleteRequest(request) {
  const accepted = buildQualifiedTranslatedStripBody(
    request.base, request.ends, request.volume, request.options,
  );
  const report = validateQualifiedTranslatedStripBody(accepted);
  return { accepted, report };
}
```

These five fields are required. IDs use ASCII letters/underscore first, then letters/digits/underscore/hyphen, with length 1..48. `resultIdPrefix` has length 1..12. The budgets are exactly 3/2/24, not requests for a partial Body. Generated evaluation, model, source, topology and certificate IDs must not collide with any complete parent context.

The bundled options are `evaluationId:'single_body_eval'`, `resultIdPrefix:'single'`, `maximumParents:3`, `maximumModels:2`, `maximumObservations:24`.

## Keep all three qualified inputs together

The constructor consumes:

- `base`: a complete `TranslatedSurfaceBaseFaceResult`.
- `ends`: a complete `TranslatedSurfaceEndFacesResult`.
- `volume`: a complete `TranslatedSurfaceStripVolumeResult`.

The same lower/upper wall results must occur in all three children, and the cap in `ends` must match the cap in `volume`. Comparison covers complete fields and represented number bits. Equal local IDs or nominal dimensions alone do not establish a matching caller context. The exposed left/right base-Line IDs and full geometry must also agree.

The six Face roles are lower wall, upper wall, original Plane cap, base, U-min end and U-max end. Their admitted orientations are forward, reverse, forward, reverse, forward and reverse. Parent loops already encode reversal in their stored Use order/senses. Preserve that effective direction once; do not flip Uses again from the Face orientation. Face orientation remains part of the support-normal/material proof.

## Interpret the copied result

The root result has thirteen fields:

```text
base, ends, volume, options, models, vertices, edges, faces,
shell, body, proof, observations, report
```

`vertices`, `edges`, `faces`, `shell` and `body` are actual new topology records. Twelve explicit qualified Curve pairs join 24 local Face vertex occurrences into eight global classes. Each shared Edge has two opposing effective Uses. Each Vertex has one connected three-germ link, and the six-Face adjacency is connected. Euler 2 is a retained invariant; it is not the whole embedding proof.

`proof` retains correspondence, vertex classes/links, Face adjacency, geometry catalog and the separate material certificate. Complete parent results and all earlier flags remain present and unchanged. Results own independent copied CPU data. They allocate no renderer or event loop; release references when no longer needed.

### Model16 plus Model2

Six native Support Surfaces and twelve unique World Curves make eighteen used geometry objects. They are represented by two actual source0 records:

| Record | Contents |
| --- | --- |
| `models[0]` | Six Supports plus the first ten World Curves: 16 objects |
| `models[1]` | The remaining two World Curves: 2 objects |

Each record retains `sourceId`, exact `source`, `sourceVersion:0` and its compiled native `model`. All eighteen used objects are covered once by `proof.geometryCatalog`. Older complete Models and unused siblings remain in the retained parents. The original per-Model 16-object compiler limit is unchanged.

A Face's `supportRef` and an Edge's `curveRef` contain both `sourceModelId` and `objectId`. Resolve them against the referenced record's `model.name`. Do not assume every object belongs to Model16:

```js
const edge = accepted.edges[11];
const record = accepted.models.find(
  item => item.model.name === edge.curveRef.sourceModelId,
);
const curve = record?.model.objects.find(
  item => item.id === edge.curveRef.objectId,
);
if (!curve || curve.kind !== 'curve') throw new Error('Unresolved qualified Curve');
```

`accepted` is the constructed result from the API module above. These source0 models carry Curve/Surface geometry; they are not a source-language `@body` declaration or a serialized universal Body format.

### Units and proof scope

Native XYZ uses authored coordinates in mm, with no axis conversion. Volume uses mm³. Native U/V and local pcurves are dimensionless, with their original domains. UV sidecars stay separate from World Curves; do not retag them as millimetre source0 geometry.

The separate material proof binds all six entire Face images to the source-defined map:

```text
Phi(u,t,w) = S_lower(u, Vmin + t*(roofV(u)-Vmin)) + [0,h*w,0]
```

Positive exact source coefficients establish the restricted map's injectivity/Jacobian and its complete outward boundary. This permits the separately named restricted Solid qualification after graph, source and material checks. Global C1 and global binary64 evaluation guarantees remain false.

The root's 24 Curve endpoint D0 comparisons have a 1e-7 mm admission limit. Those numeric observations are separate from the whole-boundary/coefficient proof. Root counts exclude retained parent-internal work. The constructor makes no new final float conversion; it retains the volume provider's conversion information.

## Diagnose refusal and retain accepted data

`QualifiedTranslatedStripBodyError` exposes `code` and the actual `cause` when wrapped. Messages are bounded to 1024 characters.

| Code | Boundary |
| --- | --- |
| `INPUT`, `IDENTITY`, `BUDGET` | Own-data shape, IDs or resource budgets |
| `PARENT`, `PAIR` | Complete parent validation or shared caller/geometry mismatch |
| `SOURCE`, `BINDING` | Qualified model/object resolution or geometry/proof binding |
| `TOPOLOGY`, `ORIENTATION` | Loop, pair, link or effective/outward direction |
| `MATERIAL`, `REPRESENTABILITY`, `NATIVE` | Restricted material proof, represented data or native observation |
| `OWNED` | Stored result snapshot/reconstruction or complete comparison refused |

A constructor refusal returns no partial Body and does not mutate caller data. Publish a candidate in host state only after the public call succeeds. The validator does not trust stored quality flags:

```js
const tampered = structuredClone(accepted);
tampered.report.quality.genericBoolean = true;
try {
  validateQualifiedTranslatedStripBody(tampered);
  throw new Error('Expected an owned-result refusal');
} catch (error) {
  if (error.code !== 'OWNED') throw error;
}
// accepted is the separate original result; the CLI revalidates and compares it.
```

The selected new CLI executed this genuine cloned-result mutation and observed `OWNED`. The separate accepted result passed deep comparison and revalidation. Setting a flag cannot turn this Body into a generic Boolean operand or certify a different model.

## Resource and file boundaries

| Resource | Limit |
| --- | --- |
| Complete Body request / result | 2097152 UTF-16 units **and** 2097152 UTF-8 bytes each, including final newline |
| Source string | 262144 characters; source compiler byte limits also apply |
| Objects per source Model | 16; this Body uses two Models with 18 used objects total |
| Parent / Model / observation budgets | Exactly 3 / 2 / 24 |
| Own values / depth | 1048576 / 64 |
| Array elements / record fields | 8192 / 64 |
| Own key / string lengths | 128 / 262144 characters |
| Rational operations / GCD steps | 200000 / 200000 |
| Rational integer bits / fraction integer characters | 8192 / 5000 |

Inputs must use bounded, dense plain own data. Getters, hidden/symbol fields, cycles, sparse arrays and foreign prototypes refuse. The API copies independent occurrences and preserves represented numeric bits. `JSON.parse` preserves numeric `-0`; ordinary `JSON.stringify` changes it to `0`. Keep the supplied request bytes unchanged. A complete Body validation is stricter than comparing rounded geometry or file text summaries.

The two-MiB limit belongs to this complete Body family. It does not enlarge every predecessor's limits or permit an eighteen-object source Model. No silent truncation, coordinate welding, rounding, clamping or source stripping qualifies a refused request.
