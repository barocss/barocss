# Bounded data and ownership

Reuse exact qualified node_bridge.py and bounds.py. Wrapper parent model/position graphs have24MiB checks before and after each frame; Node proof allocation is the unchanged integer component32MiB. Shared RPC transport is parent4MiB+child4MiB, with outgoing encoded request released before incoming reply graphs. Per reply/prefix2MiB; wrapper16MiB and outer harness16MiB account the same adopted files once within outer total (outer receipts/audits may fail the remaining allowance; no cap increase).

The wrapper is the only parent of its one Node worker. resource.getrusage(RUSAGE_CHILDREN) is sampled around that owned lifetime and collected after close/wait. No auditor runs inside the wrapper. Outer harness launches audits only after wrapper exits, so auditor CPU does not contaminate the child cost authority. All descendants inherit the outer guard group. Exact PID cleanup preserves unrelated processes. All tool hashing uses64KiB blocks; external binaries are metadata pins and excluded from source archives.

Original saved requests are bounded before JSON allocation. Outer harness parser reserves parent data under24MiB and is not concurrent with the worker parent context. During each later audit it explicitly checks the complete retained parent frame/source/report graph under24MiB; the new independent adapter bounds/reports retained plus scratch under32MiB, leaving8MiB for transport/encoding/hash within the same64MiB total. The Node has exited before this phase. This is explicit owned data, not RSS, total address-space, VM or process-runtime memory proof. Operation and bit prebounds remain in the unchanged component sources and new compact backend.
