## Frozen public contract recommendation

```ts
export interface SewOptions {
  /** mm; omitted or 0 selects the existing native automatic tolerance. */
  tol?: number;
}
// Part.sew(surfaces: readonly RawNurbsSurface[], options?: SewOptions): this
// sewSpec(surfaces, resolvedOptions): Extract<FeatureSpec,{command:'sew'}>
// FeatureSpec: { command:'sew', surfaces: readonly RawNurbsSurface[], values:{tol:number} }
```

Use `sew`, matching the existing UI verb and native feature. Use `tol`, matching the current Sew edit-field key; no `MM`/unit suffix. This follows `api-conventions.md:185-203`. `tol` is a **number, not Dim**: the existing Core/Model saved tolerance is a number, not a parameter reference (`part-model.ts:271`, Model `doc.ts:566-567`). Do not change these types/schema or promise a binding that Core cannot evaluate. Both facade backends have no Sew BINDS entry. A casted Param for tol must receive existing PARAMETER_UNBINDABLE, not become a stored unsupported reference. Exclude Sew's editor `tol` from generic bind availability as well, so UI does not offer a parameter contract that the node cannot keep. This is a narrow admission requirement for the new public route, not a runtime defect claim about legacy files.

`tol` admission: omitted/default0 means omit native `tolerance`; explicit0 is the same auto sentinel already used by DirectPanel/editFields. Finite positive values <=1 are copied exactly; negative, nonfinite, wrong-type and >1 values refuse VALUE. Do not silently clamp new input. Reuse one check for command/editor to retain this declared range. Native automatic tolerance is `max(1e-6, maxAbsControlCoordinate * 1e-3)` (`sew-solid.ts:87-90`), not a universal tight tolerance or bbox-span tolerance. It can exceed explicit1 for large coordinates; preserve existing auto semantics. Do not replace auto with0,1e-7,a chosen literal, or a larger global tolerance. A tolerance edit changes the saved matching allowance, not the source coefficients.

Use common constructor `#make`, not current-body `#act`: Sew adds one new closed body, preserves separate existing bodies and chosen-body focus, and works as the one new tool in the existing Boolean callback protocol. No union, body copy, shell thickening or target body is implicit. A raw API call carries no Direct selection and hides no Direct objects.
