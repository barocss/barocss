# Scene v11 hit mode native browser observation

Actual headed Chromium 155/WebGL2 at DPR 2, compiled public package import map in `consumer/hit-mode.html`. Canvas logical size 80×80. At logical point (20,20), the top 1×1 RGBA8 blue sprite stayed `[0,0,255,255]` in every mode. With sprite `none`, `hitTest` returned `Back` and a real pointerdown routed `Back → stage`. Switching sprite to `auto` returned `Sprite`. Setting the clipped frame to `none` returned `Back` and routed `Back → stage` while the blue pixel remained. Re-enabling the frame restored the sprite hit. Setting parent `none` also returned `Back` while the child kept authored `auto` and the pixel stayed blue. An invalid image ID under `none` returned `INVALID_ASSET` without replacing the accepted frame.

Browser Save downloaded the actual 1,299-byte v1/Scene v11 `document.json`. After page reload, file chooser Open staged a fresh canvas, renderer and display tree. It restored parent `none`, clipped frame `auto`, child `auto`, all four asset bytes `[0,0,255,255]`, blue pixel and `Back` hit. Editing the restored parent to `auto` changed hit to `Sprite`; a real pointerdown routed `Sprite → Frame → Parent → stage`. Browser console: 0 errors and 0 warnings. Screenshots capture parent `none` before Save and restored parent `auto` after Open. This fixed flow does not certify DOM pointer-events parity or other browsers/devices.
