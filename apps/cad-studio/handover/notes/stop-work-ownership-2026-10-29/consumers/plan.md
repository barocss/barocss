# D321 controlled native Worker Studio consumer plan

Plan recorded before execution; final selected PASS and both failed source profiles are in README.md/report.json. The High lane owns App and the pure operation-owner helper. This consumer
owns only the selected browser-flow case, its test-only native Worker delivery scheduler and this evidence folder.
Run only after final producer checks, source freeze and the parent's serial heavy-slot approval.

The real current-worktree Studio runs through the existing browser-flow harness on Chrome WebGPU/DPR1 and Node22.
A test init script subclasses the native Worker without replacing Worker source, postMessage input, transfers,
real result data or deferred mass payloads. Its first message listener holds original native MessageEvents FIFO
from one selected evaluate submission. It never releases/replays them. Actual termination discards that worker's
held events and late terminated-worker messages. Rearming is allowed only after the previously claimed native
Worker terminated. The helper exposes arm/snapshot for scheduling/inspection only, not an App/UI state setter.
The original `.omx/research` helper and intake evidence remain read-only.

## Minimum actual cases

1. Real Box D0 computes. Real second Box Apply accepts D1; its actual native result and mass messages finish but
   client delivery is held. Wait for the genuine D1 recovery copy before further attempts. Camera Top and Render
   workspace must remain usable without changing the accepted document. Try Grid twice: require the explicit
   pending-work refusal and exact D1 document/history/recovery preservation. Try Drawing Sheet size once if that
   always-active setting is reachable without projection readiness. If unavailable/disabled, record the precise
   NOT_RUN boundary rather than claiming Drawing wiring PASS. Stop must roll back owned D1 to exact D0, leave dirty
   true, update recovery to D0, terminate/discard old held result+mass and adopt no old events. Public Redo restores
   D1 through a new normal evaluation. A subsequent normal Grid edit and Undo must restore exact D1.
2. A new third Box Apply is held with no Render edit attempt. Normal Stop restores D1. Public Redo restores that
   third Box; Undo returns D1. A further unarmed normal Box Apply and Undo prove no permanent edit guard lock.

Raw body-count/finite-volume checks distinguish D0(1body/1000), D1(2/2000), third(3/3000) and later normal Box
(3/3200) mm³. No selection/doc/evaluation-stage hook supplies a state. Actual UI Apply, workspace/view controls,
Grid/Drawing setting controls, Stop and Undo/Redo produce all transitions. Snapshots inspect only current document,
body readiness, recovery/local history UI, worker delivery metadata and camera. They do not expose full Undo depth
or certify exact viewport geometry provenance. Source/client-delivery timing is distinct from natural long work:
the genuine worker may finish quickly while its native event delivery remains intentionally held.

Async image completion, initial unowned work, parameter candidates, all Undo/New/Open invalidations and a complete
Drawing matrix remain separate focused/source proofs or actual NOT_RUN. Pure-helper tests alone do not establish
App call-site wiring. This plan does not expand into every editing surface or natural slow scheduling. Retain first
failure text, actual UI PNGs, raw state/trace snapshots, source hashes and cleanup; no full suite, new dependency,
commit or push is part of this lane.
