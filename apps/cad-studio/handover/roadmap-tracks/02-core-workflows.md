## Status and acceptance rules

This is a work queue after the [D519 audit](../notes/cad-package-studio-audit-2026-11-04/README.md), not a new acceptance result. The 34 numbered rows remain stable scope references. They are not equal units of work or a completion percentage. Existing sketch, solid, drawing, assembly, history and project functions are implemented. Open acceptance means their remaining consumer scope needs qualification, not that the feature is absent.

P0 owns current-document completion, recovery/autosave, current 3MF, GPU equality/recovery, density, memo ownership and React errors, mass provenance and STEP metadata boundaries. Resolve an applicable P0 blocker before expanding a workflow. Keep the first failure and its source; do not replace it with a later passing run.

For each selected item, declare the input family, source references, supported operations, expected refusal and actual user consumer before implementation. Select SMALL for a private bounded repair, FEATURE for new user behavior, and FULL for a changed public contract or producer authority. Expand checks only for affected dependencies. Geometry/B-rep/tolerance changes need High review; full-kernel checks require a B-rep core change, not a prose-only change.

Every workflow closeout needs the affected focused checks and actual desktop Studio behavior. Exercise edit, rebuild, refusal retention, first Undo/Redo and own Save/fresh Open when those states are in scope. Use an independent native or file reader for numeric geometry, mass, units or exchange claims. Pixel layout and typed examples do not establish physical accuracy. Reuse evidence only for exact eligible inputs and record which current consumer is newly observed. No mobile, new dependency installation, invented budget or paid live execution is part of this plan.

Broader P1 acceptance needs an explicit family/case ledger before anyone declares the category complete.

Model/assembly owns occurrence identity, placements and mates; Studio owns selection and linked revision acceptance; drawing/BOM consumers own their current source binding. Motion and Physics activation are not part of static assembly.

Existing placement, static mates, patterns/skips, linked updates, cuts and BOM are implemented. Evidence includes [D457 linked planar mate](../notes/static-mate-linked-update-2026-11-03/README.md), [D493 constrained mates](../notes/fully-constrained-mate-workflow-2026-11-04/README.md), [D487 linked assembly cut](../notes/assembly-cut-linked-revision-2026-11-04/README.md), [D511 patterned material/BOM](../notes/patterned-material-bom-mass-2026-11-04/README.md), [D512 nested revision/BOM](../notes/nested-selection-bom-revision-2026-11-04/README.md), and [D513 transient card correction](../notes/nested-card-freshness-2026-11-04/README.md).

Remaining acceptance:

1. Insert an authored part twice, retain separate occurrence paths, place/mate it, and distinguish definition edit from occurrence placement. Confirm remaining freedom/conflict refusal within the selected mate scope.
2. Change the linked source while a nested occurrence is selected. Explicitly accept/reject it; card path, geometry, mate/reference state and BOM must name one accepted revision, including pending and superseded states.
3. Edit material and a pattern/skip value; independently check the declared quantity and numeric mass scope. Aggregate mass precision is not inferred from displayed BOM values.
4. Exercise first Undo/Redo, own Save/fresh Open and post-Open re-edit. Refusal must retain the prior assembly and avoid an unintended history entry. Current assembly export depends on P0-R03.

Finite P3 closeout is one small static assembly with repeated and nested occurrences, one supported mate chain, one linked edit and one BOM/drawing consumer. Nested in-place editing and additional mate families remain separate acceptance items. No dynamic simulation, arbitrary solver completeness or whole-assembly scale claim follows.

## Requirements and cross-track boundaries

Each case names the requirement owner, source/consumer modules, existing evidence reused, affected SMALL/FEATURE/FULL tier, actual desktop observations and numeric authority. Record PASS, FAIL, NOT_RUN and UNKNOWN separately. A retained partial checkpoint is valid work, but does not close the category.

The separate CAD React, Physics and automation tracks are defined in [Platform and extensions](03-platform-and-extensions.md). They must share the same current core/Doc/refusal rules without blocking unrelated MAIN source work. Competitor feature lists are declared claims, not measured parity or speed evidence. Root's finite B01..B10 baseline starts NOT_ADJUDICATED; this document assigns no baseline result.
