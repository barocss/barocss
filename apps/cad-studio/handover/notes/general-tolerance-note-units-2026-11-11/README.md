## Reproduction and decision

**FAIL on the parent.** Studio offers an estimate of 0.2 mm and 0.5°. Accept it on a 25.4 × 12.7 × 6.35 mm part, then switch the drawing to inch. The accepted note, screen and both actual files contain `LINEAR ±0.2 · ANGULAR ±0.5°`. The title block says inch, and the physical model still measures 25.4 mm wide. The independent reader verifies the captured old text and rejects it under the explicit-unit requirement. The two baseline runners initially expected unencoded DXF symbols and omitted the decimal padding of an exact one-inch dimension. The final reader decodes DXF text escapes and compares the dimension as a rational number. This rechecks both original file pairs without changing their bytes. Baseline receipt SHA-256 values `faf442f388fb80458802c2dff6dd8eb87e25cbe690e8d8777446d157af3f39db` and `d1472c84dc2f0e59c52e99221b970cceb35bc90ecb90cc0e2642623516e856d1`. Retained file read and rejection SHA-256 `7c3694fcbce72a3890a68cb181f22d93bfd33213153f652781e5549806a199a6`.

Generate `LINEAR ±0.2 mm · ANGULAR ±0.5°` from the same values as the suggestion. Direct Accept and Accept all store literal text in the existing Note. The estimate explanation and user acceptance boundary stay in place. The file reader and export paths keep existing authored text as saved.
