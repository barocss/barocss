# D701 — Preserve detail annotation ownership

P2 B06, row 11. [#2366](https://github.com/barocss/barocss/issues/2366). Parent `c133a5e181776503d09958fc1fb8a76eeff6f2d0`. FULL review for the existing agent drawing admission contract. Sol Medium owns implementation and verification.

## Reproduction and decision

**FAIL on the parent.** Open a 64 × 32 × 8 mm plate with a Ø8 through hole and Detail B, crop radius 6 mm. The Details list removes B and leaves its diameter and tolerance. The diameter is lost in Studio and absent in the actual SVG. Create a new B at the same center with a 7 mm crop using the detail tool. The old diameter resolves against the new B and its 0.15 mm authored tolerance returns in the exported SVG. The three independent SVG reads and browser receipt have SHA-256 `e038d6ecb96c16ed4dae44653cf8f8897a67257b35ebee53c6e091292b456fb0`.

Check the whole drawing before Remove Detail. A dimension or standalone geometric control blocks removal from the detail's sheet and from the parent marker's sheet. The drawing hint names the action to take. Once the user removes the annotations explicitly, the detail and its sheet assignment leave in one commit. A later detail can reuse the free letter.

A legacy dimension, standalone frame or sheet assignment reserves its detail letter even if the view is absent. The Studio detail tool allocates across the whole drawing. When a continuation-sheet edit collides, only the new view and its new annotations follow the assigned letter. The agent's existing `set_drawing` tool refuses an explicit collision with `DRAWING_DETAIL_REFERENCES`. It also protects referenced details from parent and crop changes. Scale and placement remain editable. The file reader keeps unresolved records and their diagnostics.
