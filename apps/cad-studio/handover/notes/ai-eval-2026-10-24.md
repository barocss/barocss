# AI evaluation — how far an AI agent gets today (2026-10-24)

The owner asked: "AI 로 어디까지 되는지 제대로 확인 해줘". This note is the capability map: a graded ladder of briefs, from
one part to a product, each given to a live AI agent through the studio's own v2 tools, each judged by an independent
oracle on the document the agent left — never by the agent's word.

**Status (interim, 2026-10-24):** 80 runs judged. Still running when this was committed: P1 run 3 and grinder run 3 (they land in the store; `rejudge` adds them). P1 runs need judging again with one `check.ts` version (the API lane's WIP gained an `outputs` check mid-run; run 1 was judged without it).

**Headline.** Through the v2 tools alone, with a person accepting proposals, Codex builds single parts, standard-size parts from person files, CNC/cast/print parts with their reports, URDF, drawings, and the **whole A9 product (3/3, 15/15 hard checks)**. Long descriptive prompts come out remarkably complete: cathedral 3/3 hit every shape element; tractor and living room nearly all. One P1 engine run passed all 7 of the API lane's checks then in force (24 parts, 67 mates, 123 cc, 720° cycle, cam 0.5, no contact, balance 0.544). Run 2 failed (stroke 0, crank touches cam). What fails is mostly *our* tool layer, not planning: see §5.

## 1. How the runs were made

- **Agent.** Codex (`codex exec`, codex-cli 0.156.1, its default model `gpt-6.1-sol`, reasoning effort high). The
  owner allows Codex with no token cap; no Claude run was made, so none of the P1-L3 US$ budget was used.
- **Tools.** The repo's cad-mcp server (`server/cadMcp.ts`, on a state file, exactly as the studio's chat server runs
  it) is Codex's only tool source: the 13 v2 tools, with nothing pasted into the prompt. Codex's own tools are off
  (shell, patch, web search, images, apps, sub-agents), the user's Codex config is not read (`--ignore-user-config`),
  and its sandbox is read-only.
- **Prompt.** The studio chat's: `TOOLSET.prompt` as the system prompt (Codex's `model_instructions_file`), and the
  user message as the chat server builds it — the state note, the brief, and the note listing the person's files.
  Per turn, the tools as listed (15,440 characters) plus the system prompt (8,242) come to 23,682 characters, under
  the 25,000 budget.
- **Autonomy L4**, as O15's run: the agent changes the part and may accept its own proposals. Assembly, mate and
  drawing proposals always need the person, so **the harness plays the person**. After each turn it accepts every
  open proposal in the order made (the studio's Accept button), then continues the conversation (`codex exec resume`)
  with what was accepted, or the refusal if one couldn't be.
- **Person-supplied files.** Rows only reach the agent as files the person attached (rule (b)): the shipped sample
  rows (`samples/rows`) and A9's fixture (`conformance/a9/rows`), received through the same person-file path as the
  chat (`receivePersonRowFiles`, `features.load_rows … file`).
- **Caps.** 160 tool calls, 4 turns and 45 minutes per run (P1: 400 calls, 8 turns, 100 minutes). The harness stops
  a run at a cap; the lanes' light gate (load below 40) runs before each.
- **Judging.** After a run, the saved part (`part.bcad`) is judged in a fresh process by the brief's oracle. The
  engine evaluates the document again and runs its own read actions on it (BOM, joints, drawing issues,
  manufacturability, CAM). Hard checks decide pass or fail. Soft checks are reported but don't decide.
- **Runs kept** (not committed), gallery-ready as the roadmap's Later list asks:
  `~/.cache/barocss-ai-eval/runs/<brief>/<run>/` holds `prompt.txt`, `part.bcad`, `render.png` (an isometric
  software render), `score.json`, `record.json` (every call with its arguments, result and time; refusals; the
  person's accepts; the agent's messages; token usage) and `events.jsonl` (Codex's raw events). `index.json`,
  `report.md` and `details.md` sit beside `runs/`.

Commands (from `apps/cad-studio`, Node 22):

```
node scripts/ai-eval/ai-eval.mjs list                      # the ladder
node scripts/ai-eval/ai-eval.mjs validate                  # every oracle on a known build (must pass)
node scripts/ai-eval/ai-eval.mjs run --runs 3 --parallel 3 # the live runs (Codex)
node scripts/ai-eval/ai-eval.mjs rejudge                   # every kept run judged again, then the report
node scripts/ai-eval/ai-eval.mjs report
```

P1 is listed when its folder has `brief.md` and `check.ts`: set `AI_EVAL_P1_DIR` to the API lane's
`examples/products/engine-1cyl` until it's merged.

## 2. The ladder and its oracles

23 ladder briefs (10 RB9 rungs, 13 of this ladder) plus P1 and 4 long prompts; `node scripts/ai-eval/ai-eval.mjs list` prints them, and `briefs.ts` / `long.ts` hold the prompts and oracles.

**Which oracles were checked, and how:**

- **RB9 rungs.** RB9's own prompts and hidden checkers, at one fixed parameter sample (seed 1, trial 5). RB9's
  mutants have shown these checkers catch what they target. `validate` runs RB9's scripted ideal agent through the
  adapter: 10/10 pass.
- **Base part as an instance.** RB9.7 and RB9.12 count parts as placed instances only, while the studio's system
  prompt tells the agent to build the fixed part as the base part. Before those two checkers judge a document whose
  base part has solids, the adapter shows the base part to them as a grounded instance: same geometry, same mates.
- **This ladder's own rungs.** Closed forms from the brief's numbers, with the row values read from the person's
  file. Each has a **reference build** through the same tools; `validate` passes 12/12 of those that have a tool
  path (all but the motion and STEP/3MF rungs, which have none). The reference builds are also evidence that the
  brief can be done with today's tools.
- **P1.** The API lane's own `check.ts`, through its `run.mjs --check`.

## 4. Where it fails

In 80 runs, 276 of 3,732 calls were refused. The families, by count: dotted op tool names in proposals (50, in 16 briefs; AE-1), `MATE_FACE_UNKNOWN` (41; AE-2), describe misses (30), unquoted requirement sources (24; AE-13), brief field rules (15), the agent's accept of an assembly proposal (12; AE-10), and kernel refusals with no reason (9; AE-7). Evaluation time matters only for large assemblies (AE-8, AE-9).

The per-turn tool budget does not: the tools plus the system prompt come to 23,682 characters, and Codex's context grows by caching (A9: 8.0 M input tokens, 7.7 M cached).
