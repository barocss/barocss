# STEP export preparation and loss visibility

The toolbar prepares STEP bytes in memory and opens one panel in the existing right dock. The panel shows the actual generated schema profile and millimetre units, the exporter's applicable loss report, and mesh representation options when visible root or placed mesh bodies exist. Only the panel's explicit Export action downloads. Cancel, Close, Escape, document edits, Open, New and worker failure discard the preparation. Generation and synchronous document/evaluation/name checks guard late results and final download.

The existing `omitted` result now also reports applicable native feature history and parameters, flattened visible assembly hierarchy and sharing, user body/occurrence labels, body/face/occurrence colours/materials, authored drawing data and reference datums. File/product names and generated face names are distinct from user labels. A plain imported STEP does not gain invented native-history or appearance losses. Existing sheet/infill refusal and omission behavior is retained. These statements describe the current exporter profile, not the capabilities of STEP as a whole. Semantic PMI and named datum system transfer remain outside this profile.

This change does not alter STEP geometry, the writer options, the source revision algorithm or the library API. Export preparation runs only for an explicit toolbar or representation action. STL retains its existing flow. Test tools use current sources; no OCP environment is installed or recreated. Actual outbound download is not exercised without owner permission.

The evaluation wire strips report metadata. A private STEP-only snapshot restores bodies, drawing and references on the received request before one exporter call. Occurrence names and looks already cross the evaluation wire. The worker header now identifies this metadata-bearing export input; it can differ from the former stripped source revision. Geometry DATA is unchanged. Direct producer bytes for identical input/options still match D406 exactly.

Independent source audit found displayed-variant and stale-appearance snapshot defects and missing drawing/datum loss messages. All were fixed. The actual run01 then found the private transport omission above. Run02 verifies six applicable losses, unchanged document and Cancel; its later outside-panel click hit the Chat overlay. Driver-only correction and remaining-only run03 verify Escape, Open/New invalidation, Close and all three mesh choices. Root reviewed the three screenshots. These are combined scoped results, not a clean whole-run02 PASS. Delayed/stale replies and final download ownership are injected-controller tests. Actual variant selection and outbound Export remain NOT_RUN. See [qualification](qualification.json) for counts, commands and retained failures.

The STEP worker request carries a private metadata snapshot beside the existing geometry wire document. The receiver restores body looks, drawing data and reference datums recursively before one exporter call. This fixes the actual-browser omission of appearance warnings found in run01. Geometry DATA is unchanged; the worker's source revision header intentionally now includes the transported export metadata instead of identifying a stripped evaluation-only document. Direct `exportStudioStep` bytes for the same input/options remain unchanged. Variant selection is covered by focused payload tests and source inspection, not actual-browser variant acceptance.
